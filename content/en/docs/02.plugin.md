## Commands

```ts
server.addCommand("/hp", (player, args) => print(player, `${player.health} HP`));
server.addCommand("/kick", kick, { access: "Kick", description: "Kick a player" });
server.addCommand("amx_heal", heal);             // no slash: a console command

function kick(player: Player, args: string[]) { ... }
```

A name with `/` is a chat command: `say /hp` and `say_team /hp` both run it,
and the line is not repeated in chat. A name without it is a console command.
`args` are the words after the name: `/kick bob now` gives `["bob", "now"]`.
A name `"say <phrase>"` is a chat line without a slash: `"say time"` runs
when someone says exactly "time" (in say or say_team), and gets no `args`.
`access` is an admin flag (`"Kick"`, `"Ban"`, …, the editor suggests them);
for a player without it the command does nothing and their chat line goes
through as usual.

The arrow's `player` and `args` need no types: `addCommand` gives them.

`cmd("say /hp", sayHp, "KICK")` from earlier versions still works, with a
handler taking `id: number`; `server.addCommand` replaces it.

::tip
Status: verified on the server 2026-09-23.
::

### Server commands

```ts
server.addServerCommand("hns_reset", (args) => reset(args.length > 0 ? args[0] : "all"));
```

A command of the server's own console: typed there, sent over rcon, or run by
another plugin's `server_cmd`. No player types it, so the handler gets only
`args`, the words after the name. It may be added from the top of the file:
the engine is told about it at `plugin_init`, because a command registered
while the file is read (during `plugin_natives`) crashed the server when it
was typed. What the handler prints while it runs goes back to whoever sent
the command - over rcon, into the rcon reply.

::tip
Status: verified on the server 2026-09-24 - every `bun run test:server` suite
is started this way.
::

## Events

```ts
server.addEventListener("putinserver", (event) => {
	print(event.player, "Welcome!");           // event.player is a Player
});

server.addEventListener("disconnected", (event) => {
	console.log(`${event.player.name} left: ${event.reason}`);
});

server.addEventListener("cfg", (event) => loadSettings());   // configs are read (plugin_cfg)

server.removeEventListener("impulse", onImpulse);             // the same function that was added
```

Like `addEventListener` in the DOM. The event name is a string the editor
completes (both spellings: `"putinserver"` and the Pawn `"client_putinserver"`),
a misspelled one is an editor and build error, and the listener gets the
event's own type - `(event) => ...` needs no annotation. The fields are the
forward's arguments, typed: a player index is a `Player`, a string a `string`,
a flag a `boolean` (`event.dropped`).

A listener written as a separate function names the event type, which is the
forward's name: `function onImpulse(event: ClientImpulseEvent) { ... }`.

Two limits of the compiler underneath:

- The name has to be written out: `server.addEventListener(name, ...)` with the
  name in a variable is a build error ("an event name that is not written out
  as a string literal").
- A listener may use anything at the top level of the file, but not a local of
  the function it is written in - AssemblyScript has no closures. The build
  says `Not implemented: Closures` at the local (after a misleading
  "used before being assigned" about the same one).

## The game's events

```ts
game.addEventListener("restartRound", (event) => console.log("a new round"));
game.addEventListener("takeDamage", (event) => {
	if (event.attacker.team == event.player.team) event.preventDefault();
});
```

The game's own functions - reapi hookchains - are events on `game`, the way
the server's are on `server`: typed by name, answered by returning a value,
blocked with `event.preventDefault()`. See [Hookchains](/docs/hooks).

## Timers

```ts
const handle = setTimeout(onTick, 2000, 42);   // in 2 s, onTick(42)
setInterval(everySecond, 1000);
clearTimeout(handle);
```

Like in the browser, with one difference: the third argument is a number the
handler receives (there are no closures).

## Time and randomness

```ts
Date.now();                          // milliseconds since 1970, a number
new Date(Date.now()).getUTCHours();  // Date as in JavaScript, UTC getters
const start = performance.now();     // milliseconds, to the microsecond
Math.random();                       // 0 <= x < 1, seeded differently each run
```

As in JavaScript: `Date` takes and gives a number. Status: verified on the
server 2026-09-23.

## Chat and console

```ts
print(id, "Only you see this");
print(0, "Everyone sees this");
print({ id, variant: "center" }, "Health restored!");   // "chat" | "center" | "console" | "notify"
console.log("to the server console");
```
