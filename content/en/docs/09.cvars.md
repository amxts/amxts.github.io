```ts
const freeze = new Cvar("mp_freezetime");
freeze.number = 5;

const speed = new Cvar("my_speed", "250");   // created with "250" if it does not exist
speed.value;       // "250" - the text, as the server keeps it
speed.number;      // 250
speed.boolean;     // true - anything but 0

speed.addEventListener("change", (event) => {
	console.log(`${event.cvar.name}: ${event.oldValue} -> ${event.value}`);
});
```

A cvar reads like an input's `value`: `value` is its text, `number` and
`boolean` read and write the same cvar as a number and as a switch. A whole
number is written as one (`"5"`, not `"5.000000"`).

The second argument is the default: the cvar is created with it when the
server has none by that name. Without it a missing cvar stays missing:
`exists` is `false`, `value` reads `""` and writes do nothing.

A change listener hears every change - from the console, `amx_cvar`, another
plugin or this one - with the old and the new text.
`removeEventListener("change", listener)` stops it.

A cvar the plugin sets goes into a constant first, made once at the top of
the file, and is set from there - not `new Cvar("mp_limitteams").number = 0`
in one line, and not `server.command("mp_limitteams 0")`:

```ts
const autoTeamBalance = new Cvar("mp_autoteambalance");
const limitTeams = new Cvar("mp_limitteams");

function startDeathmatch() {
	autoTeamBalance.number = 0;
	limitTeams.number = 0;
}
```

A `Cvar` made at the top level waits for `plugin_init` to find its cvar, so
the game's own cvars (`mp_*`, `sv_*`) are there by the time it is used.

Why one class and not `Cvar<number>`: a cvar is text underneath and gets read
either way, often both; a type parameter would make you name the kind twice
and still not stop anyone writing `mp_freezetime` as text.
