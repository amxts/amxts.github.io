`canPlayerHearPlayer` is asked by the game only while alltalk is off
(`sv_alltalk 0`); with alltalk on nobody is asked, so an answer there changes
nothing. To silence a player whatever alltalk says, use `player.muted`
([players](/docs/players)).

The game's own functions — taking damage, spawning, throwing a grenade — are
reapi hookchains, and a plugin listens to them the way a page listens to the
DOM. Who listens to what:

| object | events | example |
| --- | --- | --- |
| `server` | stock AMX Mod X events: a player joins, leaves, the map changes | `server.addEventListener("putinserver", ...)` |
| `game` | the game's functions (reapi hookchains): damage, spawn, grenades | `game.addEventListener("takeDamage", ...)` |
| `forward.subscribe` | forwards other plugins raise | `roundEnd.subscribe(...)` |

```ts twoslash
declare const player: import("~/facade").Player;
// ---cut---
import { game, TakeDamageEvent } from "~/facade";

// Answer: return a value. In a pre listener the game does not run its own.
game.addEventListener("canPlayerHearPlayer", (event) => event.listener.team == event.sender.team);

// Only block, without an answer.
game.addEventListener("traceAttack", (event) => {
	if (event.attacker.team == event.player.team) event.preventDefault();
});

// Post: read what the game answered, or return a replacement.
game.addEventListener("flPlayerFallDamage", (event) => event.result / 2, true);

// A named listener, and taking it off again.
game.addEventListener("takeDamage", onTakeDamage);
game.removeEventListener("takeDamage", onTakeDamage);

function onTakeDamage(event: TakeDamageEvent) {
	event.damage = event.damage * 2;
}
```

The event's type comes from its name: `(event) => ...` needs no annotation,
the editor completes the name and refuses a misspelled one.

## Options

The third argument, `post`: `true` runs the listener after
the game function, with its result in `event.result`. Without it the listener
runs before, and can stop the function. `removeEventListener` takes the same
`post` the listener was added with.

## What an event has

| | |
| --- | --- |
| fields | the chain's arguments, typed: `event.damage` is a number, `event.sample` a string, `event.damageType` a `Damage[]` |
| entity fields | `event.attacker`, `event.listener` are `Player`; an item is `Weapon`; anything else is `Entity`. The number is `.id`. Read-only |
| `event.player` | the player the event is about, a `Player`: `this` of a `CBasePlayer` chain, and the one reapi passes by his `index` (`playerSpawn`, `throwHeGrenade`, `playerBlind`, `showMenu`, ...) or `playerIndex` (`pmJump`, `pmDuck`, ...) — never `new Player(event.index.id)` |
| `event.x = ...` | change an argument before the game function gets it (pre); `event.x` then reads what was written |
| `return value` | the chain's answer: in pre, instead of the game (it goes no further); in post, over the game's answer |
| `event.preventDefault()` | the game function won't run; the answer is the default (0 / false) |
| `event.stopImmediatePropagation()` | like `preventDefault()`, and the listeners after this one aren't called either (`HC_BREAK`) |
| `event.result` | what the game answered — in a post listener; read-only |

A listener **either always answers or never does**: an AssemblyScript function
can't "sometimes return a value". One that answers only in some cases returns
nothing and blocks with `preventDefault()` where needed, or always answers,
repeating the game's rule for the rest. The answer type is the chain's
(`boolean`, `number`, `Player`/`Entity`): returning another is a compile error
and an editor error. A chain that answers nothing takes no answer at all.

A listener must not use a local of the function it is written in —
AssemblyScript has no closures ("Not implemented: Closures"). Module-level
variables and other functions are fine.

Assigning a name writes its number back (`event.reason = "terroristsWin"`).
A number the include does not name reads as `"unknown"` (`"none"` for
`RoundWinner` and `WeaponKind`, `"UNASSIGNED"` for `Team`), and writing
`"unknown"` leaves the argument as the game passed it. Flags the include does
not name stay as they were when the array is written.

The names and numbers are reapi's own, from `cssdk_const.inc` and
`reapi_*_const.inc`.

| option | |
| --- | --- |
| `winner` | `"TERRORIST"`, `"CT"`, `"draw"` or `"none"` — the side that scores, and the game's message and sound for such an end |
| `delay` | seconds until the next round; 5 by default |
| `message` | the centre message (or a `#CSTRIKE_` token) instead of the game's; `""` for none |
| `sound` | the radio sound instead of the game's; `""` for none |
| `dispatch` | `true`: the `roundEnd` listeners of every plugin (and Pawn's `RG_RoundEnd` hooks) hear this end, as they hear the game's own. `false` by default, as reapi's — a `roundEnd` listener that ends the round again would call itself |

`ScenarioEventEndRound` that goes with it (`ROUND_TERRORISTS_WIN`,
`ROUND_CTS_WIN`, `ROUND_END_DRAW`, `ROUND_NONE`).

## Names

The event name is the reapi name without its class, in camelCase; the reapi
name is in the tooltip:

| reapi | name | event |
| --- | --- | --- |
| `RG_CBasePlayer_TakeDamage` | `"takeDamage"` | `TakeDamageEvent` |
| `RG_CSGameRules_FlPlayerFallDamage` | `"flPlayerFallDamage"` | `FlPlayerFallDamageEvent` |
| `RH_SV_StartSound` | `"startSound"` | `StartSoundEvent` |
| `RG_CBasePlayer_Spawn` | `"playerSpawn"` | `PlayerSpawnEvent` |

The tooltip describes the event in English or Russian (`AMXTS_DOCS_LANG=en|ru`
in `.env`), or shows reapi's own Description line where no description is
written yet.

`throwHeGrenade`, `traceAttack` and a few others) read as a `Vector`, but
cannot be changed yet: assigning one does not compile.
