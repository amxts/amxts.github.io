```ts twoslash
import { Entity, Player, server } from "~/facade";

server.addCommand("/low", lowGravity);

function lowGravity(player: Player) {
	player.gravity = 0.5;
	player.renderMode = 2;
	console.log(player.classname);      // "player"
	const here = player.origin;         // a Vector: here.x, here.distanceTo(...)

	const nade = Entity.find({ classname: "grenade", owner: player });
	if (nade) nade.velocity = [0.0, 0.0, 300.0];   // any three numbers
}
```

The player comes from the event or command that is about him; an entity from
an event field, `Entity.find` or `Entity.create`.

## How properties work

`Entity` has every `entvars` field from reapi; `Player` also has every member
of `CBasePlayer` (and the classes it inherits from). A property's type is the
one reapi documents for the field:

| in reapi | property | type |
| --- | --- | --- |
| `Float:get_entvar(id, var_gravity)` | `gravity` | `number` (a float) |
| `get_entvar(id, var_origin, Float:out[3])` | `origin` | `Vector` to read, any `number[]` of three to write |
| `get_entvar(id, var_classname, dest[], len)` | `classname` | `string` |
| `get_entvar(id, var_rendermode)` | `renderMode` | `number` |
| `get_member(id, m_bNightVisionOn)` | `nightVisionOn` | `boolean` |
| flag mask (`var_flags`, `m_iHideHUD`, …) | `flags`, `hideHud`, … | array of names, see [Flags](/docs/flags) |

The name is camelCase without the prefix: `var_rendermode` → `renderMode`,
`m_iHideHUD` → `hideHud`, `m_flVelocityModifier` → `velocityModifier`. The
editor's hover tooltip says what the field means - its unit, range and
typical values - and ends with the engine's name and what it stores:
`pev->gravity`, a float; `CBasePlayer::m_iAccount`, an int.

The spare fields `iuser1`-`iuser4`, `fuser1`-`fuser4`, `vuser1`-`vuser4` and
`euser1`-`euser4` are free for a plugin's own values on any entity that is
not a player. On a player the game uses some of them: `iuser1`-`iuser3` for
spectating, `iuser4` is rewritten every frame, `fuser2` and `fuser3` are
movement. The tooltip of each says which.

Writing a float to an int field (or the other way round) does not compile.

## Vectors — `Vector`

```ts twoslash
declare const player: import("~/facade").Player;
// ---cut---
import { Player, Vector } from "~/facade";

const here = player.origin;                    // Vector
const away = here.distanceTo(other.origin);    // units
const up = new Vector(0.0, 0.0, 1.0);
player.velocity = here.subtract(target).normalize().scale(400).add(up.scale(200));
here.x; here[0];                               // the same number
```

`add`, `subtract` and `distanceTo` take any three numbers, a literal
included. `scale(n)`, `dot(v)`, `normalize()` (one unit long; zero stays
zero), and `magnitude()` for how long it is.

A `Vector` is an array of three numbers underneath, which is why a literal
still assigns, `origin[0]` still reads, and a native that takes `Float:v[3]`
takes a `Vector`. It is also why its size is `magnitude()`, not `length()`:
`length` is the array's, and it is 3.

## Finding, creating, removing

```ts twoslash
declare const player: import("~/facade").Player;
// ---cut---
import { Entity } from "~/facade";

const targets = Entity.findAll({ classname: "info_target" });
const near = Entity.findAll({ near: player.origin, radius: 200 });
const mine = Entity.findAll({ classname: "grenade", owner: player });
const bomb = Entity.find({ model: "models/w_c4.mdl" });   // Entity | null

const box = Entity.create("info_target");                // Entity | null
if (box) box.origin = player.origin;

targets[0].remove();
```

Like `querySelectorAll`, `createElement` and `remove()`. Every filter field
is optional and all given ones must match; with no filter `findAll()` is
every entity. They use the engine module, so they work without reapi.

`remove()` asks the engine to free the entity at the end of the frame
(`FL_KILLME`, how the game's own entities go), not on the spot the way
`remove_entity` does: an entity freed from inside its own touch or think, or
while something is walking the entity list, is still used after it is gone.
So within the same frame `findAll` still finds it.

## Hand-written

`Player` has properties that come from AMXX natives rather than fields:
`name`, `health`, `armor`, `frags`, `deaths`, `team` (`"TERRORIST"`, `"CT"`,
`"SPECTATOR"`, `"UNASSIGNED"`), `ip`, `authid`, `isAlive`, `isConnected`,
`isBot`. The reapi fields with the same names (`var_health`, `var_team`, …)
are not generated for `Player`.

## Weapons — `Weapon`

```ts twoslash
import { Player, server } from "~/facade";
import { Weapon } from "~/entities";   // the type is not re-exported by the facade yet

server.addCommand("/unload", unloadAll);

function unloadAll(player: Player) {
	const weapon = player.activeItem;   // Weapon | null
	if (weapon && weapon.kind == "knife") weapon.nextPrimaryAttack = 1.0;

	for (const item of player.items) unload(item);
}

function unload(weapon: Weapon) {
	weapon.clip = 0;

	const holder = weapon.player;   // Player | null: who holds it (m_pPlayer)
	if (holder) console.log(`${holder.name}: ${weapon.kind} unloaded`);
}
```

- `Weapon extends Entity`: every entvar property plus the `CBasePlayerItem`
  and `CBasePlayerWeapon` members from `reapi_gamedll_const.inc`. The
  `m_Weapon_` prefix is dropped: `m_Weapon_iClip` → `clip`,
  `m_Weapon_flNextPrimaryAttack` → `nextPrimaryAttack`.
- `kind` is which weapon it is, as a string without `WEAPON_`: `"knife"`,
  `"flashbang"`, `"smokegrenade"`, `"hegrenade"`, `"ak47"`, … (type
  `WeaponKind`; an unknown id is `"none"`). `kindId` is the same as a number,
  like the `WEAPON_*` constants.
- Pointers are objects: `player.activeItem` / `clientActiveItem` / `lastItem`
  are `Weapon | null`, `weapon.player` is `Player | null`, `weapon.next` is
  the next weapon in the same slot. Read-only.
- `player.items` is all of the player's weapons: the six `m_rgpPlayerItems`
  slots and the `m_pNext` chain behind each (grenades share slot 4).
- `weapon.owner` is `var_owner` from `Entity` (a number); the weapon's holder
  is `weapon.player`, because the entvar already took the name `owner`.

## Not there yet

- Array fields (`m_rgAmmo`, …) need an element index; `m_rgpPlayerItems` is
  covered by `player.items`.
- String `m_*` members (`m_szTeamName`, …) are not there yet.
- `var_controller`, `var_blending`.
