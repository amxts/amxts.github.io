Natives go both ways: a plugin exports its own for Pawn plugins to call, and
calls AMXX or reapi natives the facade does not cover.

## Your plugin's natives: `export function`

Every `export function` of a plugin's entry file is an AMX Mod X native under
the same name, with its real types:

```ts twoslash
import { Float } from "~/facade";

/** A value from a config file, or false when the key is not there. */
export function cfg_get_value(file: string, section: string, key: string) {
	return lookup(file, section, key);             // string | null
}

export function cfg_get_int(file: string, key: string, fallback = 0) {
	return parseInt(read(file, key)) || fallback;
}

export function cfg_get_float(file: string, key: string): Float {
	return parseFloat(read(file, key));
}

export function cfg_get_float_array(file: string, key: string): Float[] {
	return readFloats(file, key);
}

export function cfg_set_value(file: string, key: string, value: string) {
	return write(file, key, value);                // boolean
}
```

The build writes the include a Pawn plugin needs next to the plugin —
`my_plugin.inc` for `my-plugin.ts` — with the function's own comment above
each line; the deploy build (the `plugins` script with `--deploy`) copies it into the server's
`addons/amxmodx/scripting/include`:

```pawn
/** A value from a config file, or false when the key is not there. */
native bool:cfg_get_value(const file[], const section[], const key[], out[], len);
native cfg_get_int(const file[], const key[], fallback = 0);
native Float:cfg_get_float(const file[], const key[]);
native cfg_get_float_array(const file[], const key[], Float:out[], size);
native bool:cfg_set_value(const file[], const key[], const value[]);
```

```pawn
#include <my_plugin>

new value[64];
if (cfg_get_value("hns.ini", "round", "time", value, charsmax(value)))
	server_print("time = %s", value);
```

How types cross:

| TypeScript | Pawn |
| --- | --- |
| `text: string` | `const text[]`, read whole — no 255-character limit |
| `count: number` | `count` (a cell) |
| `speed: Float` | `Float:speed` |
| `flag: boolean` | `bool:flag` |
| `values: number[]` | `const values[], values_size` |
| `values: Float[]` | `const Float:values[], values_size` |
| `origin: Vector` | `const Float:origin[3]` |
| `player: Player` | `id` — a player id; see below |
| `player?: Player` | `id = 0` — 0, the server or everyone, is `null` |
| `x = 5` | `x = 5` (a literal default goes into the include; its type is read off it) |
| `text?: string` | `const text[] = ""` — left out, Pawn passes `""`, which is false: `if (text)` |
| returns `string` | `out[], len` at the end; the native returns the length written |
| returns `string \| null` | `bool:`, and `out[], len`: true with the text, or false |
| returns `number[]` / `Float[]` | `out[], size` at the end; the native returns how many it wrote |
| returns `number` / `boolean` / `Float` | the native's result: a cell, `bool:`, `Float:` |
| returns nothing | the native returns 0 |

**`Float`** is `number` to TypeScript — nothing changes where the value is
used. Pawn's `Float:` is a tag, invisible at the call site, so a native says
which of its numbers are floats by this name: on a parameter
(`speed: Float`) and on the result (`): Float {`). That is the one place a
return type is written: the body cannot say it, since to TypeScript a float
and a whole number are the same `number`. Any other result is inferred as
usual. A plugin that implements an include ([below](#implementing-an-existing-include-include))
needs no `Float` at all.

**`Player`** is a player id to Pawn — a parameter called `player` is `id` in
the include, the name AMX Mod X gives a player — and the function gets the
Player, with no `new Player(id)` and no check of its own:

An id that is no player slot (outside 1 to maxPlayers: 0, 33, -1) never
reaches the function: the native answers its result's default — 0, `false`,
`0.0`, `""` in `out[]` — the way the `if (id < 1 || id > MaxClients) return 0`
of a Pawn native would. A slot that is empty still reaches it:
`player.isConnected` is the function's to ask. `Player | null` takes 0 as
`null`, for the natives where 0 means the server or everyone; any other bad
id is refused as above. A native that has to answer something other than the
default for a bad id (`mc_get_active_menu`: -1) keeps `id: number`.

A string result is written into the caller's buffer up to `len` — the
`charsmax(out)` it passes — and never cut in the middle of a UTF-8 letter.
Text is UTF-8 both ways.

The rules:

- Only the entry file's exports are natives, and only `export function`: not
  `export const`, not a re-export. `init` and names starting with `__` are
  left out.
- A parameter of any other type — `string[]`, an object, `...args` — stops the
  build with the function and the parameter named. So does a result of another
  type.
- A native is registered while the file is read, as AMX Mod X wants it: a
  Pawn plugin loaded after `amxts_host.amxx` finds it. On a hot reload
  (`amxts_reload`, saving the file) the plugin takes its natives back under the
  same names; a native added by the reload exists only for Pawn plugins loaded
  after it.
- There is no limit on arguments; plugins may export 128 natives between
  them.
- A function stays an ordinary function too: the plugin calls it directly.

The include is looked for beside the plugin, in the plugins folder and among
the includes amxts ships. What each declaration says decides how an argument
crosses, so the function keeps plain TypeScript types — no `Float`, no tags:

| in the include | the TypeScript function |
| --- | --- |
| `Float:x`, `bool:x`, `Tag:x` | `x: number` (read as a float, a boolean, a cell) |
| `id` — a player | `player: Player` or `player?: Player` (0 is null): a bad id answers the default, as above |
| `TeamName:team` | `team: Team` — `"UNASSIGNED"`, `"TERRORIST"`, `"CT"`, `"SPECTATOR"` for 0 to 3, as a Forward's `Team`; another number answers the default, as a bad id does. A `Team` where the include has no `TeamName:` stops the build |
| `const x[] = ""` | `x?: string` — Pawn always passes text, `""` when the caller gave none |
| `const x[]` | `x: string` — or `x: number[]`, the size after it taken with it |
| `x[], len` — not const | an output: the function returns a string |
| several outputs, `&x` | the function returns an object literal — its fields fill them in order — or `null` (the native returns 0) |
| `const fmt[], any:...` | the function takes `text: string`: the text formatted as format() does it, `%L` included |
| `any:...` and more parameters | the parameters after the fixed ones are the tail: text, or a number Pawn passed by address |
| `Array:` result | a `string[]`, a `number[]` (Float cells), `string[][]`, rows of numbers (`number[][]`), or an object of those — an Array of their Arrays |
| a result nobody reads (`@noreturn`, untagged) | the function returns nothing; the native returns 0 |

Every native the include declares must be exported — the build says which
one is missing. A function the include does not declare is a native too,
declared from its TypeScript types after the include's own text. The
generated `<plugin>.inc` is the include itself: what the Pawn plugins were
compiled against.

## Calling natives directly

::warning
Typed natives with strings, floats and `...` are new: not every one of them
has been tried on a live server yet.
::

If the facade lacks what you need, call an AMXX or reapi native directly —
under the same name as in the AMXX docs, with real types:

```ts twoslash
import { client_print_color, get_gametime, get_user_info, rg_send_bartime2 } from "~/natives";
import { Player, rounded, server } from "~/facade";

server.addCommand("/plant", plant);

function plant(player: Player) {
	rg_send_bartime2(player.id, 10, 50.0);                    // Float: is a number
	const now = get_gametime();                               // a number
	const model = get_user_info(player.id, "model");          // the buffer the native fills is the result
	client_print_color(player.id, 0, `^4${model}^1 at ${rounded(now)}`);   // no format needed: ready text
}
```

How types carry over from Pawn:

| in `.inc` | here |
| --- | --- |
| `Float:x` | `number` |
| `bool:x` | `boolean` |
| `const text[]` | `string` |
| `out[], len` (filled by the native) | returned `string` |
| `Float:v[3]` | `number[]` |
| `x = 5` in the declaration | default value |
| `fmt[], any:...` | ready text (a template string) |
| `any:...` | `...args: number[]` |

The rule: **if the facade has it, use the facade** (`player.health`, not
`get_user_health(id)`); if not, call the native directly. The style test
points out where a native already has a replacement.

830 of the 950 natives, and 76 of the 79 with `...`, are typed; the rest the
facade wraps.
