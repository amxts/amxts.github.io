Player fields (`gravity`, `hideHud`, …) are in [Players and entities](/docs/entities).

## Is a module on the server

```ts
if (hasModule("reapi")) ...   // "reapi" | "cstrike" | "fun" | "hamsandwich" | "engine" | "fakemeta"
```

Not every server runs ReHLDS, and so reapi. The player actions below go
through reapi where it is present and through the standard AMX Mod X modules
(`fun`, `cstrike`, `hamsandwich`) where it isn't; the plugin chooses nothing.
A plugin asks `hasModule` itself before a native that only one module has.

## Listing players

```ts
for (const player of Player.all()) ...                      // everyone except HLTV
for (const ct of Player.all({ alive: true, team: "CT" })) ...
Player.all({ humans: true })                                // people only; { bots: true } - bots only
Player.all({ dead: true })
```

| filter field | default | what it does |
| --- | --- | --- |
| `alive` | `false` | alive only |
| `dead` | `false` | dead only |
| `team` | all | this team only |
| `bots` | `true` | whether to include bots |
| `hltv` | `false` | whether to include HLTV |

## Team

```ts
if (player.team == "CT") ...
player.team = "TERRORIST";
```

`Team = "TERRORIST" | "CT" | "SPECTATOR" | "UNASSIGNED"`. It is read from the
player itself (`m_iTeam`), not from the AMXX cache, which still shows the old
team after a switch. Writing works like `rg_set_user_team`: the model changes
to match the new team, the scoreboard learns at once, and round win
conditions are not checked — the plugin decides when to check them.

## Voice

```ts
player.muted = true;          // nobody hears him on the voice chat
if (player.muted) ...         // reading it is the check
player.muted = false;
```

Like `video.muted` in a browser. It works with alltalk on or off: the engine
applies it at the last step of voice routing, after `sv_alltalk` and the
game's rules. Verified on the server 2026-09-23.

## HUD

```ts
player.showHud("-35 HP");
player.showHud("Round 3", { color: [255, 40, 40], x: 0.02, y: 0.88, hold: 2 });
player.showHud("typed out", { effect: "typewriter", channel: 2 });
player.showHud("HIDERS WIN", { large: true, y: 0.3, hold: 5 });   // the director HUD: large letters
server.showHud("For everyone", { y: 0.6 });

const countdown = new HudLine();                 // one place on the screen
countdown.show(player, `..[${left}]..`, { hold: 1.1 });   // the next show replaces it
countdown.clear(player);
countdown.clearAll();
```

Every option can be left out and has AMX Mod X's own default: `color`
`[200, 100, 0]` (red, green, blue), `x` -1 and `y` 0.35 (0 to 1 from the
top left, -1 centres), `hold` 12 seconds, `effect` `"fade"`
(`"flicker"`, `"typewriter"`), `fadeIn` 0.1, `fadeOut` 0.2, `channel` -1
(any free one of the four; a message on the same channel replaces the last),
`effectTime` 6 (how long the flicker and typewriter effects take).

`large: true` is the director HUD (`set_dhudmessage`): larger letters, for a
result or a headline; it has no channels. A `HudLine` is a place on the
screen that holds one message - showing another there replaces it, where a
message of its own would take another channel. A countdown redrawn every
second is one: without it the last second's number is still fading out
under the new one. Underneath it is AMX Mod X's HUD sync object.

## Screen - `player.screen`

```ts
player.screen.fade({ color: [200, 0, 0, 100], duration: 0.5 });                      // a red wash that clears
player.screen.fade({ color: [0, 0, 0, 255], duration: 0.1, hold: 1, stay: true });   // black, and it stays
player.screen.fade({ color: [0, 0, 0, 0], duration: 0.2 });                          // clear again
player.screen.shake({ amplitude: 8, duration: 1, frequency: 5 });
player.screen.statusIcon("dmg_cold", "show", [0, 200, 255]);                          // "hide", "show", "flash"
player.screen.roundTime(90);                                                          // the round clock, seconds
player.screen.hideHud(["Money", "Timer"]);                                            // tell the client now
player.screen.crosshair(false);
player.screen.flashlight(false);
```

What the player sees over the world, one user message each (ScreenFade,
ScreenShake, StatusIcon, RoundTime, HideWeapon, Crosshair, Flashlight) sent
to him alone. Times are seconds; the message's own units - 1/4096 s for a
fade, 1/256 for a shake's frequency - are the hood's.

| `fade` option | |
| --- | --- |
| `color` | red, green, blue, alpha, 0 to 255; `[0, 0, 0, 255]` by default |
| `duration` | seconds the fade takes; 1 |
| `hold` | seconds the full colour holds; 0 |
| `direction` | `"in"` (the default) from the colour to a clear view, `"out"` from a clear view to the colour |
| `stay` | the colour stays until the next fade (`FFADE_STAYOUT`) |
| `modulate` | tints the picture rather than painting over it (`FFADE_MODULATE`) |

`shake`: `amplitude` up to 16 units (4 by default), `duration` seconds (1),
`frequency` shakes a second (5). `statusIcon(sprite, state, color)` takes a
sprite of `sprites/hud.txt`; a hidden icon carries no colour.

`hideHud(parts)` sends HideWeapon at once; `player.hideHud` (the member) is
what the game itself sends a frame later. A fade longer than 16 seconds is
cut to 16: the message holds no more.

## Actions

```ts
player.give("weapon_flashbang");            // or "item_kevlar", "item_assaultsuit", "item_thighpack"
player.setAmmo("weapon_flashbang", 2);      // backpack ammo
player.switchWeapon("weapon_knife");        // false if there is no such weapon
player.removeAllItems();                    // removeAllItems(true) — armor too
player.resetMaxSpeed();                     // speed for the weapon in hand
player.command("stop");                     // in his own console, as if he typed it (client_cmd)
player.respawn();
player.kill();
player.deaths = 0;                          // and the scoreboard updates
```

Weapon names are the `WeaponName` union (`"weapon_knife" | "weapon_awp" | ...`);
the editor suggests them and won't let a typo through.

Under the hood it is reapi for now (`rg_give_item`, `rg_round_respawn`, …).
Whether the facade will work without reapi is an open question in
`docs/API-DESIGN.md`; the choice is hidden inside the methods, so plugins won't
change.

## Shared player fields

```ts
// as/nhnse/player.ts - the plugin that owns the fields declares them
import "~/facade";

declare module "~/facade" {
	interface Player {
		ghost: boolean;
		semiclip: {
			enabled: true | false | "default";
			passesThrough: Player[];
		};
		hideTimer: boolean;
		frozen: boolean;
	}
}
```

```ts
// any plugin
import "~/nhnse/player";

if (player.ghost) return;
player.frozen = true;
player.kills = player.kills + 1;   // numbers and strings too

player.semiclip.enabled = true;              // one member, written at once
player.semiclip.passesThrough.push(bob);     // push writes back
player.semiclip = { enabled: "default", passesThrough: [] };
if (player.semiclip.enabled == "default") ...
```

Plugins add fields to `Player` for each other: one set of values per player,
shared by every plugin on the server, TypeScript and Pawn alike. It is how
plugins share a player's state - not bit flags, not a pair of get/set natives
per field, and not a plugin's own record (`stateOf(player)`), which is for
what nobody else needs.

- **Fields** are `boolean`, `number`, `string`, a union of string literals
  (`"red" | "blue"`, and with `true | false` among them - `true | false |
  "default"` is one value), `Player[]`, or an object of those. Never
  optional. A field never written reads `false`, `0`, `""`, `[]` - and a
  union its first string literal (`"default"`).
- **An object field** is written inline, as above, or as an interface
  declared in the same file (`badge: Badge`; that file and its importers use
  `Badge` as usual - an object literal of it holds its own values until it is
  assigned to a player). Its members are the same kinds, not objects.
  `player.semiclip` reads as a live view of the store: `player.semiclip.enabled
  = true` writes that member at once, `player.semiclip = { ... }` writes every
  member, and every read asks the module.
- **`Player[]`** reads as an array whose `push` writes back, like a flag list:
  to take a player out, assign a filtered array. `includes` and `indexOf`
  find a player by his id. A player who leaves is taken out of everyone's
  lists by the module.
- **Declaring.** A plugin adds its fields by augmenting the facade's `Player`
  in a `declare module "~/facade"` block, the way TypeScript adds to another
  module's class. The file must be a module - `import "~/facade";` makes it
  one. The plugin that owns the fields keeps the block in a small file of its
  own under `as/` (`as/nhnse/player.ts`), and every plugin that reads them
  imports that file: `import "~/nhnse/player";`. Only `interface Player { ... }`
  goes in the block.
- **Types are checked.** A misspelt field (`player.gost`) is an error in the
  editor and in the build, and so is a value of the wrong type. The build
  knows the fields of the files the plugin imports; the editor knows all of
  `as/` - so a field the editor accepts and the build calls missing means an
  `import` is missing. The same field declared with two types is an error in
  both.
- **A name Player already has is refused.** `solid` is the entity's
  `var_solid`, and a field named `solid` would replace it; the build says so,
  and the field takes another name.
- **No events.** Nothing is told when a field changes: read it when you need
  it. Every read asks the module, so a value another plugin has just written
  is there. A plugin that has to act on a change - nhnse builds resemiclip's
  masks from `player.semiclip` - compares `Player.revision("semiclip")`, a
  number that goes up whenever that field changes on anyone (written by any
  plugin, TS or Pawn, or dropped when a player leaves; writing the value
  already there is no change), with the one it saw last, once a frame:

  ```ts
  let applied = 0;
  server.addEventListener("frame", () => {
  	if (Player.revision("semiclip") != applied) sync();   // sync() sets applied
  });
  ```
- **When it resets.** A player's fields are cleared when he leaves
  (`client_disconnected`, after every plugin's `disconnected` listener has
  run, so a listener can still read them): the next player in the slot starts
  clean. Everyone's are cleared when the map changes, because every plugin
  starts over with the map. `xen_reload` keeps them - the players are still
  there.

Under the hood: AssemblyScript has neither module augmentation nor a property
looked up by name, so the build (`scripts/player-fields.ts`) takes the
`declare module "~/facade"` blocks out of the files it reads, generates a
getter and a setter per field and adds them to the facade's `class Player`
itself. They call the module's store (`runtime/src/module.cpp`), keyed by
player slot and field name. An object field is a generated class in the
facade, whose members are accessors over dotted keys (`semiclip.enabled`);
the store counts changes per field name (`player_data_revision`).

### From Pawn

`#include <xen>` (`runtime/host/xen.inc`; `bun run plugins --deploy` copies it
into the server's `scripting/include`). The key is the field's name as the TS
plugin writes it:

```pawn
if (xen_get_player_data(id, "ghost")) ...
xen_set_player_data(id, "ghost", 1);

new Float:speed = xen_get_player_data_float(id, "speed");
xen_set_player_data_float(id, "speed", 1.5);

new tag[32];
xen_get_player_data_string(id, "tag", tag, charsmax(tag));
xen_set_player_data_string(id, "tag", "VIP");

// A member of an object field: its dotted key.
new enabled[16];
xen_get_player_data_string(id, "semiclip.enabled", enabled, charsmax(enabled));
xen_set_player_data_string(id, "semiclip.enabled", "true");
```

| native | what it does |
| --- | --- |
| `xen_get_player_data(id, const key[])` | a number field, whole; a boolean is 1 or 0 |
| `xen_set_player_data(id, const key[], value)` | sets a number or boolean field |
| `Float:xen_get_player_data_float(id, const key[])` | a number field as a `Float` |
| `xen_set_player_data_float(id, const key[], Float:value)` | sets a number field |
| `xen_get_player_data_string(id, const key[], out[], len)` | a text field; returns the bytes written, cut where a UTF-8 letter starts |
| `xen_set_player_data_string(id, const key[], const value[])` | sets a text field |

A field read as the other kind (a text field through `xen_get_player_data`)
reads 0 or `""`. A union of literals is text: `true | false | "default"` is
`"true"`, `"false"` or `"default"`, and `""` before anyone wrote it (TS reads
that as the first literal, `"default"`). `Player[]` is text too, the ids
with commas: `"3,5"`.

nhnse's `nhnse_get_user_bit` / `nhnse_set_user_bit` stay for the compiled
nhnse modules: for `BIT_GHOST`, `BIT_SEMICLIP_BLOCK` and `BIT_HIDE_TIMER` they
read and write `player.ghost`, `player.semiclip.enabled == false` and
`player.hideTimer`; `nhnse_set_user_semiclip` sets `player.semiclip.enabled`
(`SC_FORCE_ON` - `true`, `SC_FORCE_OFF` - `false`, `SC_DEFAULT` -
`"default"`); `nhnse_is_player_frozen` reads `player.frozen`.
