A forward is an event a plugin declares and other plugins — Pawn and
TypeScript — hear. The arguments are the type parameters:

```ts twoslash
import { Forward } from "~/facade";

const roundStart = new Forward("my_on_round_start");
const roundEnd = new Forward<RoundWinner>("my_on_round_end");   // myplugin.inc: forward my_on_round_end(WinStatus:status);
const configChanged = new Forward<string, string>("my_on_config_changed");

roundStart.emit();
roundEnd.emit("TERRORIST");
configChanged.emit(key, value);
```

A Pawn plugin catches it like any other forward: `public my_on_round_end(status)` —
`status` is `WINSTATUS_TERRORISTS`, as the plugin's include
(`plugin({ include: "myplugin.inc" })`) declares it.

The handler's parameters take the forward's types, so an arrow needs no
annotations and the editor rejects a handler of the wrong type. A plugin may
subscribe to a forward it emits itself.

**Where it can come from.** A forward emitted by a TypeScript plugin reaches
every subscriber. A forward a Pawn plugin creates reaches TypeScript only if
it is declared in one of the includes amxts is built with (AMX Mod X's, reapi's
and the other includes amxts ships): AMX Mod X calls a forward by the name of a
public function, and amxts has one for exactly those.

## Argument types

| type parameter | what Pawn gets |
| --- | --- |
| `number` | an integer cell (`FP_CELL`) |
| `boolean` | 1 or 0 |
| `string` | a string (`FP_STRING`) |
| `Player` | his id, a cell; a subscriber gets a `Player` back |
| `Team` | its `TeamName` number (`TEAM_UNASSIGNED` 0, `TERRORIST` 1, `CT` 2, `SPECTATOR` 3) — where an include declares the forward |
| `RoundWinner` | its `WinStatus` number (`"none"` 0, `"CT"` 1, `"TERRORIST"` 2, `"draw"` 3) — where an include declares the argument `WinStatus:` |
| `number` for a `Float:` argument | a float (`FP_FLOAT`) — where an include declares the forward |

**The Pawn declaration decides.** When the forward is declared in an include —
the plugin's own contract (`plugin({ include })`) or any include amxts ships
(AMX Mod X's, reapi's, ...) — the build reads how each argument crosses:

`Team` is a string in the compiled code, so without the declaration there is
nothing to say Pawn wants a number, and the build refuses rather than send the
text `"CT"`:

- `Forward<Team>` (or `RoundWinner`) for a forward no include declares — a
  build error; declare the forward;
- a `RoundWinner` where the declaration is not `WinStatus:` — a build error;
- a string where the declaration has a cell (`Forward<Player, string>` for
  `TeamName:iTeam`) — a build error;
- another number of arguments than the declaration has — a build error.

A forward no include declares crosses as its types say, as before.

At most three arguments.

## When it is created

On the first `emit`, or earlier with `create()`. The server finds who catches
the forward at the moment it is created, so create it no earlier than when all
plugins have loaded (`server.addEventListener("cfg", ...)`). It is created
once. Subscribing does not create it.
