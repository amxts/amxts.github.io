amxts is a framework for writing AMX Mod X plugins for Counter-Strike 1.6 in
TypeScript. A plugin is an ordinary `.ts` file: familiar types, classes,
`async`/`await`, events you listen to. The server runs it next to your Pawn
plugins, and the two call each other.

## Why

Pawn is small: one numeric type, 32-bit cells, no classes, no `Map`, no
closures over data, no asynchrony. Every plugin past a few hundred lines works
around the same gaps. In amxts you write what TypeScript has:

- `number`, `string`, `boolean`, arrays, `Map`, classes and interfaces;
- closures: a listener or a timer uses the variables around it;
- `async`/`await`, promises and cancellation with `AbortSignal`;
- events as in the DOM: `server.addEventListener("putinserver", ...)`,
  `game.addEventListener("takeDamage", ...)` for reapi's hookchains, with
  `event.preventDefault()`;
- players and entities as objects: `player.health = 100`, `player.team`,
  `player.hideHud.push("Money")`;
- an editor that knows every native, every reapi hookchain and every entity
  field, with their types — a typo is a red line, not a runtime error;
- tests that run your plugin without a game server ([testing](/docs/testing));
- save a file and the running server reloads it ([getting started](/docs/getting-started)).

## How it works

1. `plugin.ts` is compiled with AssemblyScript to WebAssembly: `plugin.wasm`.
2. `wamrc` compiles that ahead of time to machine code: `plugin.aot`.
3. The `amxts_amxx` module loads it inside AMX Mod X and runs it.

There is no interpreter on the hot path: on a measured frame loop the same
logic runs about three times faster than in Pawn.

A native is called by name, like in Pawn: the natives of AMX Mod X, of every
module the server loads — reapi, fakemeta, hamsandwich and the rest — and of
other plugins. Their declarations are generated from the `.inc` files, so a
TypeScript plugin calls them with TypeScript types.

Pawn plugins keep working as they are. A TypeScript plugin can export natives
for them, declared by the same `.inc` a Pawn plugin would compile against
([natives](/docs/natives)), and forwards go both ways ([forwards](/docs/forwards)).

## What the server needs

We recommend **ReHLDS with ReGameDLL and reapi**: that is the setup amxts is
built and tested on.

- AMX Mod X 1.9 or later.
- reapi for the game's events (`game.addEventListener`), which needs ReHLDS
  and ReGameDLL. The player actions work without it too: they fall back to the
  standard modules — fun, cstrike, hamsandwich ([players](/docs/players)).
- A Windows server: the `amxts_amxx` module is built and tested for Win32.

::warning
**Plain HLDS is not tested**<br>
The `amxts_amxx` module does not depend on ReHLDS, but amxts has never been
run on the original HLDS, and without reapi the game's events are not there.
Use ReHLDS.
::

## Modules

A module is TypeScript other plugins import. The core does not include any:
a server gets only the modules you add. The official ones, kept by the amxts
authors:

- **menu-core** — menus from ini files or code: conditions, placeholders,
  lists ([menus](/modules/menu-core));
- **config-core** — ini configs: sections, typed values, paths
  ([INI configs](/modules/config-core));
- **http** — `fetch` for plugins ([http](/modules/http)).

More are in the [modules catalog](/modules), and you can write your own
([creating a module](/docs/modules)).
