Files the way Node reads them:

```ts
import * as fs from "~/fs";

const text = fs.readFileSync("addons/amxmodx/configs/hns.ini");
if (text == null) return;                                  // no such file

fs.writeFileSync("addons/amxmodx/data/last-map.txt", server.map);
fs.appendFileSync("addons/amxmodx/logs/rounds.log", `${server.map}\n`);

if (fs.existsSync("addons/amxmodx/configs/hns.ini")) ...
const maps = fs.readdirSync("maps");                       // ["de_dust2.bsp", ...], or null
```

And as promises, for `await`:

```ts
const text = await fs.readFile("addons/amxmodx/configs/hns.ini");
await fs.writeFile("addons/amxmodx/data/last-map.txt", server.map);

fs.readFile("missing.txt").catch((error) => console.log(error.message));
// ENOENT: no such file or directory, open 'missing.txt'
```

| sync | promise | what it does |
| --- | --- | --- |
| `readFileSync(path)` → `string \| null` | `readFile(path)` → `Promise<string>` | the whole file as text |
| `writeFileSync(path, text)` → `boolean` | `writeFile(path, text)` → `Promise<void>` | replaces the file |
| `appendFileSync(path, text)` → `boolean` | `appendFile(path, text)` → `Promise<void>` | adds to its end, making it if needed |
| `existsSync(path)` → `boolean` | `exists(path)` → `Promise<boolean>` | a file or a folder is there |
| `readdirSync(path)` → `string[] \| null` | `readdir(path)` → `Promise<string[]>` | the names in a folder, without `.` and `..` |

**Paths** are relative to the game folder (`cstrike/`), as for any AMX Mod X
plugin: configs are under `addons/amxmodx/configs/`, data under
`addons/amxmodx/data/`. When a server keeps them somewhere else,
`get_localinfo("amxx_configsdir")` and `get_localinfo("amxx_datadir")` from
`~/natives` say where (Pawn's `get_configsdir()` is a stock over the same).
There is no helper for them yet: the universal_config port will show whether
one is worth having.

**Text** is UTF-8 both ways, and a file is read whole whatever its size -
there is no 255-character line buffer. A byte-order mark at the start is kept,
as in Node.

**Failure** differs from Node in one way: AssemblyScript has no exceptions,
so the synchronous functions say it by their result - `null` from
`readFileSync` and `readdirSync`, `false` from `writeFileSync` and
`appendFileSync` (a folder that is not there, say). The promise versions
reject with an `Error` whose message starts with `ENOENT`, as Node's do.

The work is synchronous underneath - AMX Mod X reads files on the server's
own thread - so a promise version is settled by the time it returns, and
`await` on it continues on the next job.

Under the hood: AMX Mod X's file natives - `fopen`, `fread_blocks` (128 bytes
a call), `fputs` (500 bytes a call), `file_exists`, `dir_exists`, `open_dir` /
`next_file` - in `as/fs.ts`. In a test the fake server keeps a game folder in
memory: `server.writeFile(path, text)` before the plugin reads,
`server.file(path)` after it writes - see [Testing](/docs/testing).
