Модуль — код на TypeScript, который импортируют другие плагины: файл
`modules/<name>.ts` в папке плагинов, импорт — `~/modules/<name>`. То, что он
экспортирует, — функции и типы — и есть его API. menu-core, universal-config и
http — модули.

## Устройство

```
addons/amxts/plugins/
├── modules/
│   └── greeter.ts      модуль
└── greeter.ts          его плагин: один экземпляр на сервер
```

Модуль сам по себе собирается в каждый плагин, который его импортирует: у
каждого своя копия со своим состоянием. Если у модуля есть плагин с тем же
именем, экземпляр на сервере один — см. [общие модули](/ru/docs/shared-modules). В
этом же плагине живут нативы модуля для Pawn-плагинов ([нативы](/ru/docs/natives)).

## Модуль

```ts twoslash
// modules/greeter.ts
import { Player, print } from "~/facade";

const greeted: string[] = [];

/** Здоровается с игроком раз за карту. */
export function greet(player: Player) {
	if (greeted.includes(player.name)) return;

	greeted.push(player.name);
	print(player, `Hello, ${player.name}!`);
}

/** Со сколькими игроками поздоровались. */
export function count() {
	return greeted.length;
}
```

Пишется как любой код плагина: тот же фасад, те же правила. Состояние модуля —
его собственное; другие плагины меняют его экспортированными функциями, а не
экспортированными переменными.

## Его плагин

```ts twoslash
// greeter.ts
import { plugin } from "~/facade";
import "~/modules/greeter";

plugin({ name: "Greeter", version: "1.0.0", author: "you", description: "Greets players" });
```

В `plugins.ini` он стоит раньше плагинов, которые пользуются модулем.

## Как пользоваться

```ts twoslash
declare const player: import("~/facade").Player;
// ---cut---
import { server } from "~/facade";
import * as greeter from "~/modules/greeter";

server.addEventListener("putinserver", event => greeter.greet(event.player));
```

Все плагины пишут один и тот же импорт. Пока работает плагин модуля, список
поприветствованных у них общий.

## Модуль поверх другого модуля AMX Mod X

Модуль может оборачивать сторонний модуль или плагин AMX Mod X —
`~/modules/http` оборачивает easy_http. При первом вызове он проверяет, что
нужное загружено, и пишет в лог одну понятную строку вместо ошибки о
пропавшем нативе. Что ему нужно, пишется в README — чтобы владелец сервера
знал, что поставить.

## Как поделиться

::warning
**Пока не пакет**<br>
Установка модуля через менеджер пакетов ещё делается. До тех пор модулем
делятся файлами: `modules/<name>.ts` и его плагин копируются в папку плагинов.
::

[Каталог модулей](/ru/modules) показывает пакеты из npm. Чтобы модуль туда
попал, его публикуют с `package.json`, где есть ключевое слово `amxts-module` и
ещё одно — для категории:

```json
{
  "name": "amxts-module-greeter",
  "version": "1.0.0",
  "description": "Greets players once per map",
  "keywords": ["amxts-module"],
  "repository": "https://github.com/you/amxts-module-greeter",
  "files": ["modules/greeter.ts", "greeter.ts"]
}
```

| ключевое слово | категория |
| --- | --- |
| `amxts-menus` | меню |
| `amxts-config` | конфигурация |
| `amxts-network` | сеть |

Потом `npm publish`. Каталог перечитывает npm в течение часа; на странице
модуля показывается его README.
