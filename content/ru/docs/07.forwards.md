Статус: проверено на сервере 2026-09-23 - `emit`, `subscribe` (строки и числа,
обработчик с меньшим числом параметров, `unsubscribe`) и форвард Pawn-плагина,
дошедший до `subscribe`.

Форвард - это событие, которое плагин объявляет, а другие плагины - на Pawn и
на TypeScript - слышат. Аргументы задаются параметрами типа:

```ts
import { Forward } from "~/facade";

const roundStart = new Forward("nhnse_on_round_start");
const roundEnd = new Forward<RoundWinner>("nhnse_on_round_end");
const configChanged = new Forward<string, string>("nhnse_on_config_changed");

roundStart.emit();
roundEnd.emit("TERRORIST");
configChanged.emit(id, value);
```

Pawn-плагин ловит его как любой форвард: `public nhnse_on_round_end(status)` -
`status` равен `WINSTATUS_TERRORISTS`, как объявлено в include.

## Подписка из TypeScript

```ts
const greeted = new Forward<string, number>("showcase_on_greeted");

greeted.subscribe((name, count) => {
	console.log(`${name} зашёл в ${count}-й раз`);   // name: string, count: number
});

greeted.subscribe(onGreeted);
greeted.unsubscribe(onGreeted);

function onGreeted(name: string) { ... }   // может брать меньше параметров, чем у форварда
```

Параметры обработчика получают типы форварда, поэтому стрелке аннотации не
нужны, а обработчик неверного типа редактор не пропустит. Плагин может
подписаться на форвард, который отправляет сам.

**Откуда он может прийти.** Форвард, отправленный из TypeScript-плагина,
доходит до всех подписчиков. Форвард, созданный Pawn-плагином, доходит до
TypeScript, только если он объявлен в include, из которого собран host-плагин
(форварды `nhnse_on_*` - да): AMX Mod X вызывает форвард по имени public-функции,
а у host есть такие функции ровно для них.

## Типы аргументов

| параметр типа | что получает Pawn |
| --- | --- |
| `number` | целая ячейка (`FP_CELL`) |
| `boolean` | 1 или 0 |
| `string` | строка (`FP_STRING`) |
| `Player` | его id, ячейка; подписчик получает обратно `Player` |
| `Team` | её номер `TeamName` (`TEAM_UNASSIGNED` 0, `TERRORIST` 1, `CT` 2, `SPECTATOR` 3) - если форвард объявлен в include |
| `RoundWinner` | его номер `WinStatus` (`"none"` 0, `"CT"` 1, `"TERRORIST"` 2, `"draw"` 3) - если аргумент объявлен в include как `WinStatus:` |
| `number` для аргумента `Float:` | дробное (`FP_FLOAT`) - если форвард объявлен в include |

**Решает Pawn-объявление.** Если форвард объявлен в include - контракте
плагина (`plugin({ include })`) или любом include, который знает сборка
(`includes/`, include AMX Mod X), - сборка читает, как проходит каждый
аргумент:

```ts
// forward nhnse_on_player_joined_team(id, TeamName:iTeam);
const joined = new Forward<Player, Team>("nhnse_on_player_joined_team");
joined.emit(player, "CT");                     // Pawn получает (id, 2)
joined.subscribe((player, team) => ...);       // team: "CT"
```

В собранном коде `Team` - строка, поэтому без объявления нечему сказать, что
Pawn ждёт число, и сборка отказывает, а не отправляет текст `"CT"`:

- `Forward<Team>` (или `RoundWinner`) для форварда, которого нет ни в одном
  include, - ошибка сборки; объявите форвард;
- `RoundWinner` там, где в объявлении не `WinStatus:`, - ошибка сборки;
- строка там, где в объявлении ячейка (`Forward<Player, string>` для
  `TeamName:iTeam`, `GameMode` для `GameModeType:`), - ошибка сборки;
- другое число аргументов, чем в объявлении, - ошибка сборки.

Форвард, которого нет ни в одном include, проходит по своим типам, как и
раньше.

Не больше трёх аргументов.

## Когда он создаётся

При первом `emit` или раньше, через `create()`. Сервер находит, кто ловит
форвард, в момент его создания, поэтому создавать его стоит не раньше, чем
загрузятся все плагины (`server.addEventListener("cfg", ...)`). Создаётся один раз.
Подписка его не создаёт.

## Остановка

```ts
const vote = new Forward<number>("my_vote");
vote.stopWhen = "handled";   // первый Pawn-обработчик, вернувший PLUGIN_HANDLED, останавливает его
```

По умолчанию `"never"`: форвард слышат все. Задаётся до первого `emit`.
