Нативы ходят в обе стороны: плагин отдаёт свои Pawn-плагинам и вызывает
нативы AMXX и reapi, которых нет в фасаде.

## Свои нативы плагина: `export function`

Статус: проверено на сервере 2026-09-23 - Pawn-плагин вызвал их со строками
(и в 1000 символов), float, массивами, вектором, boolean, значениями по
умолчанию и `string | null`: 25 из 25. Без сервера:
`tests/plugin-natives.test.ts`.

Каждая `export function` входного файла плагина — натив AMX Mod X с тем же
именем и настоящими типами:

```ts
import { Float } from "~/facade";

/** Значение из файла настроек или false, если ключа нет. */
export function cfg_get_value(file: string, section: string, key: string) {
	return lookup(file, section, key);             // string | null
}

export function cfg_get_int(file: string, key: string, fallback = 0) {
	return parseInt(read(file, key)) || fallback;
}

export function cfg_get_float(file: string, key: string): Float {
	return parseFloat(read(file, key));
}

export function cfg_get_float_array(file: string, key: string): Float[] {
	return readFloats(file, key);
}

export function cfg_set_value(file: string, key: string, value: string) {
	return write(file, key, value);                // boolean
}
```

Сборка кладёт рядом с плагином include для Pawn — `dist-wasm/my_plugin.inc`
для `my-plugin.ts`, — над каждой строкой комментарий самой функции:

```c
/** Значение из файла настроек или false, если ключа нет. */
native bool:cfg_get_value(const file[], const section[], const key[], out[], len);
native cfg_get_int(const file[], const key[], fallback = 0);
native Float:cfg_get_float(const file[], const key[]);
native cfg_get_float_array(const file[], const key[], Float:out[], size);
native bool:cfg_set_value(const file[], const key[], const value[]);
```

```c
#include <my_plugin>

new value[64];
if (cfg_get_value("hns.ini", "round", "time", value, charsmax(value)))
	server_print("time = %s", value);
```

Как переходят типы:

| TypeScript | Pawn |
| --- | --- |
| `text: string` | `const text[]`, читается целиком — без предела в 255 символов |
| `count: number` | `count` (ячейка) |
| `speed: Float` | `Float:speed` |
| `flag: boolean` | `bool:flag` |
| `values: number[]` | `const values[], values_size` |
| `values: Float[]` | `const Float:values[], values_size` |
| `origin: Vector` | `const Float:origin[3]` |
| `player: Player` | `id` - номер игрока; см. ниже |
| `player?: Player` | `id = 0` - 0, сервер или все, - это `null` |
| `x = 5` | `x = 5` (значение-литерал попадает в include, тип читается из него) |
| `text?: string` | `const text[] = ""` - если не передан, Pawn передаёт `""`, а она ложна: `if (text)` |
| возвращает `string` | `out[], len` в конце; натив возвращает длину записанного |
| возвращает `string \| null` | `bool:` и `out[], len`: true и текст или false |
| возвращает `number[]` / `Float[]` | `out[], size` в конце; натив возвращает, сколько записал |
| возвращает `number` / `boolean` / `Float` | результат натива: ячейка, `bool:`, `Float:` |
| ничего не возвращает | натив возвращает 0 |

**`Float`** для TypeScript — это `number`, там, где значение используется,
ничего не меняется. `Float:` в Pawn — тег, в месте вызова его не видно, поэтому
натив говорит этим именем, какие его числа дробные: у параметра
(`speed: Float`) и у результата (`): Float {`). Это единственное место, где
тип возврата пишется: тело его сказать не может — для TypeScript дробное и
целое одно и то же `number`. Любой другой результат выводится как обычно.

**`Player`** для Pawn - номер игрока (параметр `player` в include называется
`id`, как игрока зовут в AMX Mod X), а функция получает сам Player - без
`new Player(id)` и без своей проверки:

```ts
export function nhnse_freeze_player(player: Player) {
	frost.freeze(player);
}

/** 0: все. */
export function nhnse_sync_knife_status(player?: Player) {
	if (player == null) knife.sync();
	else knife.syncPlayer(player);
}
```

Номер, который не слот игрока (вне 1..maxPlayers: 0, 33, -1), до функции не
доходит: натив отвечает значением по умолчанию своего результата - 0,
`false`, `0.0`, `""` в `out[]`, - как ответил бы Pawn-натив с
`if (id < 1 || id > MaxClients) return 0`. Пустой слот доходит:
`player.isConnected` функция спрашивает сама. `Player | null` принимает 0 как
`null` - для нативов, где 0 значит сервер или всех; остальные плохие номера
отсекаются так же. Натив, которому на плохой номер нужно ответить не
значением по умолчанию (`mc_get_active_menu`: -1), остаётся с `id: number`.

Строка-результат пишется в буфер вызывающего не длиннее `len` — того
`charsmax(out)`, что он передал, — и никогда не режется посреди буквы UTF-8.
Текст в обе стороны — UTF-8.

Правила:

- Нативы — только экспорты входного файла и только `export function`: не
  `export const`, не реэкспорт. `init` и имена на `__` пропускаются.
- Параметр другого типа — `string[]`, объект, `...args` — останавливает сборку
  с именем функции и параметра. Результат другого типа — тоже.
- Натив регистрируется, пока файл читается, как этого хочет AMX Mod X:
  Pawn-плагин, загруженный после `xen_host.amxx`, его находит. При горячей
  перезагрузке (`xen_reload`, сохранение файла) плагин забирает свои нативы
  под теми же именами; натив, добавленный перезагрузкой, видят только
  Pawn-плагины, загруженные после неё.
- Предела на число аргументов нет; всего плагины вместе отдают до 128
  нативов.
- Функция остаётся и обычной функцией: плагин вызывает её напрямую.

Под капотом (`scripts/plugin-natives.ts`): трансформ добавляет рядом со
входным файлом скрытый файл с обёрткой на каждый натив. Обёртка читает
аргументы Pawn-вызова (`arg_string`, `arg_array` в модуле — прямо в памяти
вызывающего), вызывает функцию и пишет результат обратно (`set_arg_text`,
`set_arg_array`); модуль читает аргументы через `get_param`, пока натив ещё
выполняется.

### Свой вариант готового include: `include`

Статус: так сделаны nhnse-core (47 нативов `nhnse_core.inc`) и
universal-config (28 нативов `universal_config.inc`); проверено на
поддельном сервере и `bun run test:server` (`nhnse`: Pawn-плагин, собранный
против include).

Плагин, который заменяет Pawn-плагин, называет его include, и include
становится контрактом:

```ts
plugin({ name: "NHNSE Core", version: "1.0.0", author: "kukson", include: "nhnse_core.inc" });

export function nhnse_get_config_float(id: string) { return config.real(id); }        // Float:... - из include
export function nhnse_get_chat_prefix(player?: Player) { ... }                       // (szPrefix[], iLen, id = 0)
export function nhnse_chat_print_mg(target: Player | null, text: string) { ... }       // (id, const fmt[], any:...)
export function nhnse_get_cvar_info_by_plugin(pluginId: number, index: number) {       // (..., szName[], iNameLen,
	const info: CvarInfo = { name, langKey, pointer };                                  //  szLangKey[], iLangLen, &iCvarPtr)
	return info;                                                                        // или null: натив вернёт false
}
```

Include ищется рядом с плагином, в `as/` и в `includes/` репозитория. Как
пройдёт аргумент, решает объявление, поэтому у функции обычные типы
TypeScript - ни `Float`, ни тегов:

| в include | в функции на TypeScript |
| --- | --- |
| `Float:x`, `bool:x`, `Tag:x` | `x: number` (читается как дробное, булево, ячейка) |
| `id` - игрок | `player: Player` или `player?: Player` (0 - null): на плохой номер - значение по умолчанию, как выше |
| `TeamName:team` | `team: Team` - `"UNASSIGNED"`, `"TERRORIST"`, `"CT"`, `"SPECTATOR"` для 0-3, как `Team` у `Forward`; на другой номер - значение по умолчанию, как на плохой номер игрока. `Team`, где в include нет `TeamName:`, - ошибка сборки |
| `const x[] = ""` | `x?: string` - Pawn всегда передаёт текст, `""`, если вызывающий ничего не дал |
| `const x[]` | `x: string` - или `x: number[]`, вместе с размером после него |
| `x[], len` - не const | выход: функция возвращает строку |
| несколько выходов, `&x` | функция возвращает объектный литерал - его поля заполняют выходы по порядку - или `null` (натив вернёт 0) |
| `const fmt[], any:...` | функция берёт `text: string`: текст, отформатированный как format(), с `%L` |
| `any:...` и ещё параметры | параметры после обязательных - хвост: текст или число, которое Pawn передал по адресу |
| результат `Array:` | `string[]`, `number[]` (ячейки Float), `string[][]`, строки чисел (`number[][]`) или объект из них - Array их Array |
| результат, который никто не читает (`@noreturn`, без тега) | функция ничего не возвращает; натив вернёт 0 |

Каждый натив из include должен быть экспортирован - сборка назовёт
пропущенный. Функция, которой нет в include, тоже натив: её объявление
выводится из типов TypeScript и дописывается после текста include.
Сгенерированный `dist-wasm/<плагин>.inc` - сам include: то, против чего
собраны Pawn-плагины.

### `nativeFn` — старый способ

```ts
nativeFn("xen_answer", answer);
function answer() { ret(42); }
```

Работает, и теперь с любым числом аргументов (`arg(i)`, `argText(i)` дальше
четырёх ячеек). Для нового кода — `export function`.

В тесте `server.native(name, ...args)` вызывает экспортированный натив так же,
как Pawn, и отдаёт то, что прочитал бы Pawn, — см. [Тесты](/ru/docs/testing).

## Нативы напрямую

Статус: собирается; типизированные обёртки (строки, дробные, `...`) ждут проверки на сервере — до этой сессии нативы вызывались в сыром виде.

Если в фасаде нужного нет, натив AMXX или reapi вызывается напрямую — под тем
же именем, что в документации AMXX, и с настоящими типами:

```ts
import { rg_send_bartime2, get_gametime, get_user_name, ExecuteForward, show_hudmessage } from "~/natives";
import { rounded } from "~/facade";

rg_send_bartime2(id, 10, 50.0);                   // Float: - просто число
const now = get_gametime();                       // дробное
const name = get_user_name(id);                   // буфер, который натив заполняет, — это результат
show_hudmessage(id, `-${rounded(damage)} HP`);    // формат не нужен: готовый текст
ExecuteForward(handle, winner);                   // хвост `...` — обычные аргументы
```

Как типы переходят из Pawn:

| в `.inc` | здесь |
| --- | --- |
| `Float:x` | дробное (`f64`) |
| `bool:x` | `boolean` |
| `const text[]` | `string` |
| `out[], len` (натив заполняет) | возвращаемая `string` |
| `Float:v[3]` | `f64[]` |
| `x = 5` в объявлении | значение по умолчанию |
| `fmt[], any:...` | готовый текст (шаблонная строка) |
| `any:...` | `...args: number[]` |

Правило выбора: **есть в фасаде — через фасад** (`player.health`, а не
`get_user_health(id)`), нет — натив напрямую. Style-тест подсказывает, где у
натива уже есть замена.

Генератор: `scripts/generate-wasm-api.ts` → `as/natives.ts`,
`as/constants.ts`. Типизировано 830 из 950 нативов и 76 из 79 нативов с `...`;
остальные — в сыром виде, их оборачивает фасад.
