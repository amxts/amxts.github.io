## async и await

Это `async`/`await` из JavaScript:

- `async`-функция сразу возвращает `Promise` и выполняется до первого
  `await`. То, что она возвращает, становится значением промиса:
  `async function count() { return 3; }` - это `Promise<number>`.
- Вызов без `await` не ждёт: `countdown(player)` идёт сам по себе, а строка
  после вызова выполняется сразу.
- `await promise` отдаёт значение промиса, когда оно появится. Остаток
  функции выполняется позже - в том кадре, где пришло значение, - а сервер
  тем временем занят всем остальным. Даже `await` уже выполненного промиса
  сначала даёт закончить то, что идёт сейчас, как в JavaScript.
- `await` можно писать только в `async`-функциях, стрелках и методах.

`async`-функция может быть обработчиком везде, где нужен обработчик:
`server.addEventListener`, `game.addEventListener`, `server.addCommand`,
`Forward.subscribe` и `"change"` у квара. То, что она сообщает игре, идёт в
счёт, только если сказано **до первого `await`**: значение `return` у
обработчика игры, `event.preventDefault()`, обработанная команда. Как только
функция ждёт, игра уже пошла дальше и ответа от неё не получит - обработчик
просто продолжится позже.

```ts
game.addEventListener("flPlayerFallDamage", async (event) => {
	if (safe) return 0;          // ответ цепочки: урона от падения нет
	await sleep(100);
	return 0;                    // поздно - урон уже нанесён
});
```

## Promise

Глобальный `Promise`, как в JavaScript: `then`, `catch`, `finally`,
`Promise.resolve`, `Promise.reject`, `Promise.all`, `Promise.allSettled`,
`Promise.race` и `Promise.any`.

```ts
const [first, second] = await Promise.all([fetch(a), fetch(b)]);
const fastest = await Promise.race([fetch(a), fetch(b)]);

fetch(url)
	.then((response) => console.log(`${response.status}`))
	.catch((error) => console.error(error.message));
```

`new Promise((resolve, reject) => ...)` оборачивает API с колбэком.
Исполнитель запускается сразу; функция здесь не может пользоваться
локальными переменными вокруг (замыканий нет), поэтому `resolve` держат на
уровне файла и вызывают из колбэка:

```ts
let answered: ((value?: string) => void) | null = null;

function ask(player: Player) {
	return new Promise<string>((resolve) => {
		answered = resolve;
		showMenu(player);
	});
}

function onMenuChoice(choice: string) {
	const resolve = answered;
	if (resolve) resolve(choice);
}
```

- Колбэк `.then` возвращает значение. Чтобы сделать один запрос после
  другого, ждите их через `await`.

### Promise.all и allSettled: кортеж

Промисы разных типов, записанные прямо в вызове, дают кортеж, как в
TypeScript, - у каждого значения свой тип:

```ts
const [response, _] = await Promise.all([fetch(url), sleep(1000)]);    // Response, void
const [count, name] = await Promise.all([countAsync(), nameAsync()]);  // number, string

const [page, rank] = await Promise.allSettled([fetch(a), rankAsync()]);
if (page.status == "fulfilled") print(player, page.value.text);
if (rank.status == "rejected") console.error(rank.reason.message);
```

- Промисы одного типа или список в переменной дают массив, как и раньше:
  `(await Promise.all(list)).length`.
- Кортеж читают деструктуризацией или индексом, записанным числом:
  `results[0]`. Индекс за его концом - ошибка компиляции, как в TypeScript.
  `for...of`, `.map` и `.length` - для массивов.
- До 8 промисов разных типов в одном вызове.
- `allSettled` выполняется, когда все промисы завершились, как угодно. У
  каждого результата есть `status` - `"fulfilled"` со `value` или
  `"rejected"` с `reason` (`Error`). Отказ, который он увидел, не считается
  необработанным.

### Promise.race и any: одно значение

`race` завершается так же, как первый завершившийся промис. `any` берёт
первое значение и пропускает отказы; если отклонены все, он отклоняется с
`AggregateError`, в `errors` которого - все причины.

```ts
const response = await Promise.race([fetch(url), sleep(3000)]);   // Response | null
if (!response) return;                                            // победил sleep
print(player, response.text);

const fastest = await Promise.any([fetch(mirrorA), fetch(mirrorB)]);
```

Значение одно, поэтому и тип у промисов нужен один:

- один и тот же тип - значение этого типа;
- `Promise<void>` (`sleep`, async-функция без значения) рядом с одним типом -
  значение этого типа или `null`. Редактор пишет `Response | void`, а
  `if (!response) return` читается одинаково в обоих;
- классы с общим базовым классом - значение этого класса
  (`Promise.race([cat(), dog()])` - это `Animal`).

Остальное - например, число и строка - ошибка компиляции:
`Promise.race of 'number' and 'string': their values share no type. Await
them one by one, or give them a common base class.` В TypeScript это было бы
`number | string` - объединение, которое AssemblyScript не может хранить.

## Ошибки

`try`/`catch` нет: в AssemblyScript нет исключений. Отказ (rejection) идёт
тем же путём, каким шло бы исключение:

- его получает `.catch`;
- `await` отклонённого промиса завершает ждущую функцию на этом месте, и её
  собственный промис отклоняется той же ошибкой - вверх до того, у кого есть
  `.catch`;
- если его никто не обработал, в консоль идёт одна строка, как пишет Node:
  `Unhandled promise rejection: <сообщение>`. Отмена (ошибка с именем
  `AbortError` или `TimeoutError`) ожидаема и в лог не пишется.

Отклоняйте через `new Error(message)`; `error.message` и `error.name`
читаются обратно.

Падение внутри `async`-функции - индекс за границей, null - после `await`
пишет в консоль имя плагина и снимает только эту функцию; плагин и сервер
работают дальше.

## sleep

```ts
await sleep(1000);
await sleep(5000, { signal: AbortSignal.timeout(2000) });   // отказ через 2 с
```

Промис, который выполняется через `ms` миллисекунд. Под капотом - таймер
сервера (`set_task`), точность - кадр сервера.

## Отмена: AbortController и AbortSignal

Как в браузере:

```ts
const controller = new AbortController();
fetch(url, { signal: controller.signal }).catch((error) => console.log(error.name)); // "AbortError"
controller.abort();

controller.signal.aborted;          // true
controller.signal.reason;           // Error, с которым отменили
controller.signal.addEventListener("abort", (event) => console.log("отменён"));

await fetch(url, { signal: AbortSignal.timeout(3000) });   // "TimeoutError" через 3 с
```

- `fetch(url, { signal })` отменяет запрос (`ezhttp_cancel_request`) и
  отклоняется причиной сигнала - ошибкой с именем `AbortError`, если в
  `abort()` не передали другую.
- `sleep(ms, { signal })` останавливает свой таймер и отклоняется так же.
- `AbortSignal.timeout(ms)` отменяется сам, ошибкой с именем
  `TimeoutError`; `AbortSignal.abort()` уже отменён;
  `AbortSignal.any([a, b])` отменяется вместе с тем, кто раньше.
- Таймеры - `sleep` и `AbortSignal.timeout` - тикают раз в 0,1 с, как в
  AMX Mod X: `timeout(1)` сработает примерно через 100 мс.

### Когда игрок уходит

`player.signal` отменяется, когда этот игрок отключается (стандартный
форвард `client_disconnected`), а следующий игрок в этом слоте получает
новый:

```ts
const stats = await fetch(url, { signal: player.signal });
```

`async`-**обработчику команды** или **события игрока** (`putinserver`,
`connect`, `authorized` и другие, у чьего события есть `player`) не нужно и
этого: он работает под сигналом этого игрока. Любой `await` в нём - fetch,
sleep, любой промис - тихо завершается, когда игрок уходит: без строки в
консоли и без уборки:

```ts
server.addCommand("/rank", async (player) => {
	const rank = await fetch(`https://example.com/rank/${player.authid}`);  // отменится, если он уйдёт
	print(player, rank.text);                                                // тогда не выполнится
});
```

`signal`, переданный явно, работает вместе с ним: кто отменится первым.
`async`-функции, вызванные из такого обработчика, работают под тем же
сигналом. Обработчики игры (хукчейнов) и сами события ухода его не получают.

## Мир после await

Функция, которая ждала, продолжается в одном из следующих кадров, и многое
могло измениться: раунд закончился, игрок умер - или ушёл. Под сигналом
игрока уход завершает функцию за вас; в остальных случаях после `await`
проверьте `player.isConnected`, прежде чем снова обращаться к игроку.

## Ограничения

- `for await` и асинхронные генераторы не поддерживаются.
- Типы-кортежи в аннотациях не пишутся: `const pair: [number, string]` не
  компилируется. Кортеж получается из `Promise.all`/`allSettled` и
  деструктурируется там, где его ждут.
- `Promise.all([promise, 5])`: каждый элемент должен быть промисом; обычное
  значение оборачивают в `Promise.resolve(5)`.
- `await` принимает `Promise`; `await` обычного значения - ошибка компиляции.
- `async`-стрелка не может пользоваться локальными переменными вокруг (нет
  замыканий); её собственные параметры - можно.
- Ждущая `async`-функция хранит своё состояние в 4 КБ; той, которой нужно
  больше, снимают с сообщением, где названо имя плагина.
- Цена: код, который может дойти до `await`, - `async`-функции и то, что
  вызывает их напрямую, - инструментирует Asyncify из Binaryen; в плотном
  цикле там он примерно на 20% медленнее. Остальное не меняется, а плагин без
  `async`-функций собирается ровно как раньше.
