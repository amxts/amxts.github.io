amxts запускает плагины для Counter-Strike 1.6, написанные на TypeScript,
внутри AMX Mod X, рядом с вашими плагинами на Pawn. Плагин — обычный файл
`.ts`: игроки — объекты, у событий есть типы, а редактор знает каждое поле
игры. На этой странице — проект, первый плагин, как перезагружать его во
время работы и чем язык отличается от привычного TypeScript.

## Проект

Проект — папка с плагинами, модулями, которыми он пользуется, и одним файлом
настроек, `amxts.config.ts`, как у приложения на Nuxt — `nuxt.config.ts`:

```
my-server/
├── package.json
├── amxts.config.ts
├── tsconfig.json       { "extends": "./.amxts/tsconfig.json" }
└── plugins/
    └── hello.ts
```

```sh [npm]
npm install -D @amxts/core @amxts/universal-config @amxts/menu-core
```

```sh [pnpm]
pnpm add -D @amxts/core @amxts/universal-config @amxts/menu-core
```


`defineConfig` глобальная — импорт не нужен. `modules` перечисляет
пакеты-модули проекта; настройки каждого модуля пишутся под его ключом
(`menus` — у menu-core), и редактор проверяет их по модулю. `pluginsDir`
(`"plugins"`) и `outDir` (`"dist"`) говорят, где плагины и куда пишет сборка.
Другая сторона — [свой модуль](/ru/docs/modules).

```sh
npx amxts build            # плагины и плагины модулей в dist/, с plugins.ini
npx amxts build --deploy   # и копирует их на сервер
npx amxts dev              # собирает, выкладывает и снова — на каждое сохранение
npx amxts typecheck        # проверяет проект так же, как редактор
```

`plugins.ini` сборка пишет сама: сначала модули, каждый после тех, что ему
нужны, потом плагины проекта. Ещё она пишет `.amxts/tsconfig.json`, который
расширяет `tsconfig.json` проекта: так редактор знает `~/facade`, модули по
именам и настройки в `amxts.config.ts` (`npx amxts prepare` пишет только его).

::tip
**Bun**<br>
Сборка пока работает на [Bun](https://bun.sh): `npx amxts` запускается через
Node и передаёт работу Bun, поэтому Bun должен быть установлен.
::

## Первый плагин

```ts twoslash
import { Player, plugin, print, server } from "~/facade";

plugin({ name: "Hello", version: "1.0.0", author: "you", description: "An example" });

server.addCommand("/hp", sayHp);
server.addEventListener("putinserver", (event) => {
	print(0, `${event.player.name} joined`);
});

function sayHp(player: Player) {
	print(player, `${player.name}, your HP: ${player.health}`);

	if (player.health < 50) player.health = 100;
}
```

Файл кладётся в `plugins/` проекта, затем — `npx amxts build --deploy`.
Плагин работает и без проекта: файл `.ts` в `addons/amxts/plugins`, с именем в
`plugins.ini`, сервер сам компилирует при сохранении и загружает без смены
карты.

## Горячая перезагрузка

```sh
npx amxts dev
```

`dev` собирает и выкладывает все плагины, затем следит за папкой ваших
плагинов и модулями проекта. Когда вы сохраняете файл, она пересобирает плагины, которые его
импортируют, копирует их на сервер и перезагружает запущенный сервер через
rcon:

```
rebuilt my-plugin (6.8s) -> deployed -> reloaded
  [amxts] reloading
```

Изменение общего файла пересобирает все плагины, которые его импортируют.
Ошибка компиляции выводится как `file.ts:строка:столбец - сообщение`, над
строкой, на которую она указывает. На сервере остаётся последняя удачная
сборка.

- `AMXTS_SERVER` в `.env` указывает, где сервер, как и для `--deploy`.
- Перезагрузка идёт через rcon на `127.0.0.1:27015` (другой порт задаётся
  через `AMXTS_PORT`). Пароль берётся из `rcon_password` в `cstrike/server.cfg`
  сервера. Без пароля модуль всё равно сам перезагружает изменённый `.aot`,
  но его ответа вы не увидите.
- **Новый** плагин записывается в `plugins.ini`, но загрузится только после
  перезапуска сервера. `dev` об этом сообщит.
- Если сервер не запущен, команда только собирает и выкладывает плагины.
  Она никогда не запускает и не останавливает hlds.

## Главное о языке

Плагин — обычный TypeScript, но компилируется AssemblyScript'ом в WebAssembly.
Отличия, которые видны:

- `number` — число JavaScript, целое или дробное: `7 / 2` — `3.5`, а
  `` `${hp}` `` печатает `"100"`. Побитовые операции берут его как int32, как
  в JS. Ячейка Pawn — целое, но переводить ничего не нужно: нативы и фасад
  делают это сами.
- Обработчик — именованная функция, а не замыкание, которое захватывает
  переменные: захват AssemblyScript не поддерживает.
- Юнион строк (`"Money" | "Timer"`) работает как в TypeScript: редактор
  подсказывает и проверяет, компилятор видит `string`. Открытый юнион, в
  который годится и любая другая строка, пишется как в TypeScript: `"normal" |
  "dm" | (string & {})` — редактор по-прежнему подсказывает литералы. Других
  юнионов, кроме `T | null`, нет.
- `a ?? b` и `a ??= b` — как в TypeScript: правая часть берётся, только когда
  левая `null` (не `""` и не `0`), и `ini.getValue(section, "KEY") ?? ""` —
  это `string`.
- Функция идёт туда, где тип функции длиннее, как в TypeScript:
  `server.addCommand("/gel", gel)` с `function gel(player: Player)` получает
  игрока, а аргументы не видит — обёртка `(player, args) => gel(player)` не
  нужна.
