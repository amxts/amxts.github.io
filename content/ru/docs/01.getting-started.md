Справочник для разработчиков и агентов: как написать плагин для CS 1.6 на
TypeScript. Из этих страниц потом собирается веб-документация, поэтому каждая
написана так, чтобы её можно было прочитать отдельно.

Что будет и почему так решено — `docs/API-DESIGN.md`. Как писать код —
скилл `code-style`. Здесь — только то, что уже есть.

## Первый плагин

```ts
import { Player, print, cmd, plugin, server } from "~/facade";

plugin({ name: "Hello", version: "1.0.0", author: "you", description: "An example" });

cmd("say /hp", sayHp);
server.addEventListener("putinserver", (event) => {
	print(0, `${event.player.name} joined`);
});

function sayHp(id: number) {
	const player = new Player(id);
	print(id, `${player.name}, your HP: ${player.health}`);

	if (player.health < 50) player.health = 100;
}
```

Файл кладётся в `addons/xen/plugins`, имя — в `plugins.ini`. Сервер сам
компилирует его при сохранении и загружает без смены карты. Из репозитория:
`bun run plugins -- --deploy`.

## Горячая перезагрузка: `bun run dev`

```sh
bun run dev
```

Команда собирает и выкладывает все плагины, затем следит за `as/`. Когда вы
сохраняете файл, она пересобирает плагины, которые его импортируют, копирует их
на сервер и перезагружает запущенный сервер через rcon:

```
rebuilt nhnse-core (6.8s) -> deployed -> reloaded
  [xen] reloading
```

Изменение фасада или библиотеки пересобирает все плагины, которые её
импортируют. Ошибка компиляции выводится как `as/file.ts:строка:столбец -
сообщение`, над строкой, на которую она указывает. На сервере остаётся
последняя удачная сборка.

- `XEN_SERVER` в `.env` указывает, где сервер, как и для `--deploy`.
- Перезагрузка идёт через rcon на `127.0.0.1:27015` (другой порт задаётся
  через `XEN_PORT`). Пароль берётся из `rcon_password` в `cstrike/server.cfg`
  сервера. Без пароля модуль всё равно сам перезагружает изменённый `.aot`,
  но его ответа вы не увидите.
- **Новый** плагин записывается в `plugins.ini`, но загрузится только после
  перезапуска сервера (`bun run server`). Команда об этом сообщит.
- Если сервер не запущен, команда только собирает и выкладывает плагины.
  Она никогда не запускает и не останавливает hlds.

## Главное о языке

Плагин — обычный TypeScript, но компилируется AssemblyScript'ом в WebAssembly.
Отличия, которые видны:

- `number` — число JavaScript, целое или дробное: `7 / 2` — `3.5`, а
  `` `${hp}` `` печатает `"100"`. Побитовые операции берут его как int32, как
  в JS. Ячейка Pawn — целое, но это забота капота: нативы и фасад переводят
  сами.
- Обработчик — именованная функция, а не замыкание, которое захватывает
  переменные: захват AssemblyScript не поддерживает.
- Юнион строк (`"Money" | "Timer"`) работает как в TypeScript: редактор
  подсказывает и проверяет, компилятор видит `string`. Открытый юнион, в
  который годится и любая другая строка, пишется как в TypeScript: `"normal" |
  "dm" | (string & {})` - редактор по-прежнему подсказывает литералы. Других
  юнионов, кроме `T | null`, нет.
- `a ?? b` и `a ??= b` — как в TypeScript: правая часть берётся, только когда
  левая `null` (не `""` и не `0`), и `ini.getValue(section, "KEY") ?? ""` —
  это `string`.
- Функция идёт туда, где тип функции длиннее, как в TypeScript:
  `server.addCommand("/gel", gel)` с `function gel(player: Player)` получает
  игрока, а аргументы не видит - обёртка `(player, args) => gel(player)` не
  нужна.
