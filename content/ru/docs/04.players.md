## Есть ли модуль на сервере

```ts
if (hasModule("reapi")) ...   // "reapi" | "cstrike" | "fun" | "hamsandwich" | "engine" | "fakemeta"
```

Не на каждом сервере стоит ReHLDS, а значит reapi. Действия игрока ниже идут
через reapi, где он есть, и через стандартные модули AMX Mod X (`fun`,
`cstrike`, `hamsandwich`), где его нет; плагин ничего не выбирает. Сам плагин
спрашивает `hasModule` перед нативом, который есть только в одном модуле.

## Список игроков

```ts
for (const player of Player.all()) ...                      // все, кроме HLTV
for (const ct of Player.all({ alive: true, team: "CT" })) ...
Player.all({ humans: true })                                // только люди; { bots: true } - только боты
Player.all({ dead: true })
```

| поле фильтра | по умолчанию | что делает |
| --- | --- | --- |
| `alive` | `false` | только живые |
| `dead` | `false` | только мёртвые |
| `team` | все | только эта команда |
| `bots` | `true` | считать ли ботов |
| `hltv` | `false` | считать ли HLTV |

## Команда

```ts
if (player.team == "CT") ...
player.team = "TERRORIST";
```

`Team = "TERRORIST" | "CT" | "SPECTATOR" | "UNASSIGNED"`. Читается из самого
игрока (`m_iTeam`), а не из кэша AMXX, который после смены команды ещё
показывает старую. Запись — как `rg_set_user_team`: модель под новую команду,
табло узнаёт сразу, условия победы раунда не проверяются — когда их
проверять, решает плагин.

## Голос

```ts
player.muted = true;          // его никто не слышит в голосовом чате
if (player.muted) ...         // прочитать - это и есть проверка
player.muted = false;
```

Как `video.muted` в браузере. Работает при включённом и выключенном alltalk:
движок применяет его на последнем шаге маршрутизации голоса, после
`sv_alltalk` и правил игры. Проверено на сервере 2026-09-23.

## HUD

```ts
player.showHud("-35 HP");
player.showHud("Раунд 3", { color: [255, 40, 40], x: 0.02, y: 0.88, hold: 2 });
player.showHud("печатается", { effect: "typewriter", channel: 2 });
player.showHud("ПРЯЧУЩИЕСЯ ПОБЕДИЛИ", { large: true, y: 0.3, hold: 5 });   // director HUD: крупные буквы
server.showHud("Всем", { y: 0.6 });

const countdown = new HudLine();                 // одно место на экране
countdown.show(player, `..[${left}]..`, { hold: 1.1 });   // следующий show заменяет прошлый
countdown.clear(player);
countdown.clearAll();
```

Любую опцию можно опустить, у каждой - умолчание AMX Mod X: `color`
`[200, 100, 0]` (красный, зелёный, синий), `x` -1 и `y` 0.35 (от 0 до 1 от
левого верхнего угла, -1 - по центру), `hold` 12 секунд, `effect` `"fade"`
(`"flicker"`, `"typewriter"`), `fadeIn` 0.1, `fadeOut` 0.2, `channel` -1
(любой свободный из четырёх; сообщение в тот же канал заменяет прежнее),
`effectTime` 6 (сколько длятся эффекты flicker и typewriter).

`large: true` - director HUD (`set_dhudmessage`): крупные буквы, для итога или
заголовка; каналов у него нет. `HudLine` - место на экране под одно
сообщение: следующее, показанное там, заменяет прежнее, а не занимает
другой канал. Так рисуется отсчёт, который обновляется каждую секунду: без
этого прошлая цифра ещё гаснет под новой. Под капотом - HUD sync object
AMX Mod X.

Статус `large`, `effectTime`, `HudLine`: поддельный сервер (`tests/nhnse-core.test.ts`);
на сервере - в составе nhnse-core, `bun run test:server`.

Статус: проверено на сервере 2026-09-23.

## Экран - `player.screen`

```ts
player.screen.fade({ color: [200, 0, 0, 100], duration: 0.5 });                      // красная вспышка, которая гаснет
player.screen.fade({ color: [0, 0, 0, 255], duration: 0.1, hold: 1, stay: true });   // чёрный, и остаётся
player.screen.fade({ color: [0, 0, 0, 0], duration: 0.2 });                          // снова чисто
player.screen.shake({ amplitude: 8, duration: 1, frequency: 5 });
player.screen.statusIcon("dmg_cold", "show", [0, 200, 255]);                          // "hide", "show", "flash"
player.screen.roundTime(90);                                                          // часы раунда, секунды
player.screen.hideHud(["Money", "Timer"]);                                            // сказать клиенту сейчас
player.screen.crosshair(false);
player.screen.flashlight(false);
```

То, что игрок видит поверх мира, - по одному пользовательскому сообщению
(ScreenFade, ScreenShake, StatusIcon, RoundTime, HideWeapon, Crosshair,
Flashlight) только ему. Время - в секундах; единицы самого сообщения -
1/4096 с у затемнения, 1/256 у частоты тряски - забота капота.

| опция `fade` | |
| --- | --- |
| `color` | красный, зелёный, синий, альфа, от 0 до 255; по умолчанию `[0, 0, 0, 255]` |
| `duration` | сколько секунд идёт затемнение; 1 |
| `hold` | сколько секунд держится полный цвет; 0 |
| `direction` | `"in"` (по умолчанию) - от цвета к чистому экрану, `"out"` - от чистого экрана к цвету |
| `stay` | цвет остаётся до следующего затемнения (`FFADE_STAYOUT`) |
| `modulate` | подкрашивает картинку, а не закрашивает её (`FFADE_MODULATE`) |

`shake`: `amplitude` до 16 единиц (по умолчанию 4), `duration` в секундах (1),
`frequency` - толчков в секунду (5). `statusIcon(sprite, state, color)` берёт
спрайт из `sprites/hud.txt`; у скрытой иконки цвета нет.

`hideHud(parts)` отправляет HideWeapon сразу; `player.hideHud` (поле) игра
сама отправит кадром позже. Затемнение дольше 16 секунд обрезается до 16:
больше сообщение не вмещает.

Статус: поддельный сервер (`tests/screen.test.ts`, `server.userMessages`); на
сервере - в составе nhnse-core (чёрный экран на отсчёте, лёд),
`bun run test:server`.

## Действия

```ts
player.give("weapon_flashbang");            // или "item_kevlar", "item_assaultsuit", "item_thighpack"
player.setAmmo("weapon_flashbang", 2);      // запас в рюкзаке
player.switchWeapon("weapon_knife");        // false, если такого нет
player.removeAllItems();                    // removeAllItems(true) — вместе с бронёй
player.resetMaxSpeed();                     // скорость по оружию в руках
player.command("stop");                     // в его собственной консоли, как будто он набрал (client_cmd)
player.respawn();
player.kill();
player.deaths = 0;                          // и табло обновляется
```

Имена оружия — юнион `WeaponName` (`"weapon_knife" | "weapon_awp" | ...`),
редактор подсказывает и не пропустит опечатку.

Под капотом сейчас reapi (`rg_give_item`, `rg_round_respawn`, …). Будет ли
фасад работать без reapi — открытый вопрос в `docs/API-DESIGN.md`; выбор
основы спрятан внутри методов, так что плагины при этом не меняются.

## Общие поля игрока

```ts
// as/nhnse/player.ts - плагин, которому принадлежат поля, объявляет их
import "~/facade";

declare module "~/facade" {
	interface Player {
		ghost: boolean;
		semiclip: {
			enabled: true | false | "default";
			passesThrough: Player[];
		};
		hideTimer: boolean;
		frozen: boolean;
	}
}
```

```ts
// любой плагин
import "~/nhnse/player";

if (player.ghost) return;
player.frozen = true;
player.kills = player.kills + 1;   // числа и строки тоже

player.semiclip.enabled = true;              // один член, пишется сразу
player.semiclip.passesThrough.push(bob);     // push пишет обратно
player.semiclip = { enabled: "default", passesThrough: [] };
if (player.semiclip.enabled == "default") ...
```

Плагины добавляют поля в `Player` друг для друга: один набор значений на
игрока, общий для всех плагинов сервера, и TypeScript, и Pawn. Так плагины
делятся состоянием игрока - не битовыми флагами, не парой нативов get/set на
каждое поле и не собственной записью плагина (`stateOf(player)`), которая -
для того, что больше никому не нужно.

- **Поля** - `boolean`, `number`, `string`, юнион строковых литералов
  (`"red" | "blue"`, и с `true | false` среди них - `true | false |
  "default"` одно значение), `Player[]` или объект из них. Необязательных
  нет. Поле, в которое ещё не писали, читается как `false`, `0`, `""`, `[]`,
  а юнион - как его первый строковый литерал (`"default"`).
- **Поле-объект** пишется прямо в объявлении, как выше, или интерфейсом,
  объявленным в том же файле (`badge: Badge`; этот файл и те, что его
  импортируют, пользуются `Badge` как обычно - объектный литерал держит свои
  значения, пока его не присвоят игроку). Члены - те же виды, не объекты.
  `player.semiclip` читается как живой вид на хранилище:
  `player.semiclip.enabled = true` пишет этот член сразу,
  `player.semiclip = { ... }` пишет все члены, и каждое чтение спрашивает
  модуль.
- **`Player[]`** читается как массив, чей `push` пишет обратно, как список
  флагов: чтобы убрать игрока, присвойте отфильтрованный массив. `includes` и
  `indexOf` ищут игрока по номеру. Ушедшего игрока модуль убирает из списков
  всех.
- **Объявление.** Плагин добавляет свои поля, дополняя `Player` фасада в
  блоке `declare module "~/facade"` - так в TypeScript дополняют класс
  другого модуля. Файл должен быть модулем - его делает таким
  `import "~/facade";`. Плагин-владелец держит этот блок в маленьком
  отдельном файле в `as/` (`as/nhnse/player.ts`), а каждый плагин, который их
  читает, импортирует этот файл: `import "~/nhnse/player";`. В блоке - только
  `interface Player { ... }`.
- **Типы проверяются.** Опечатка в поле (`player.gost`) - ошибка и в
  редакторе, и в сборке, как и значение не того типа. Сборка знает поля
  файлов, которые плагин импортирует, а редактор - всего `as/`: если
  редактор поле принимает, а сборка говорит, что его нет, не хватает
  `import`. Одно поле, объявленное с двумя типами, - ошибка и там, и там.
- **Имя, которое у Player уже есть, отвергается.** `solid` - это `var_solid`
  сущности, и поле `solid` заменило бы его; сборка об этом говорит, и поле
  получает другое имя.
- **Событий нет.** Об изменении поля никто не сообщает: читайте его, когда
  нужно. Каждое чтение спрашивает модуль, так что значение, только что
  записанное другим плагином, уже на месте. Плагин, которому нужно
  действовать на изменение (nhnse строит маски resemiclip из
  `player.semiclip`), раз в кадр сравнивает `Player.revision("semiclip")` -
  число, которое растёт при каждом изменении этого поля у кого угодно (запись
  любого плагина, TS или Pawn, или сброс при уходе игрока; запись того же
  значения - не изменение), - с тем, что видел в прошлый раз:

  ```ts
  let applied = 0;
  server.addEventListener("frame", () => {
  	if (Player.revision("semiclip") != applied) sync();   // sync() ставит applied
  });
  ```
- **Когда сбрасывается.** Поля игрока очищаются, когда он уходит
  (`client_disconnected`, после всех слушателей `disconnected`, так что
  слушатель ещё может их прочитать): следующий игрок в этом слоте начинает с
  чистого листа. Поля всех игроков очищаются при смене карты, потому что все
  плагины со сменой карты начинают заново. `xen_reload` их сохраняет - игроки
  никуда не делись.

Под капотом: в AssemblyScript нет ни дополнения модулей, ни свойства по имени
из строки, поэтому сборка (`scripts/player-fields.ts`) вынимает блоки
`declare module "~/facade"` из прочитанных файлов, генерирует геттер и сеттер
на каждое поле и добавляет их в сам `class Player` фасада. Они обращаются к
хранилищу модуля (`runtime/src/module.cpp`) по слоту игрока и имени поля.
Поле-объект - сгенерированный класс в фасаде, его члены - аксессоры по ключам
с точкой (`semiclip.enabled`); хранилище считает изменения по имени поля
(`player_data_revision`).

### Из Pawn

`#include <xen>` (`runtime/host/xen.inc`; `bun run plugins --deploy` кладёт
его в `scripting/include` сервера). Ключ - имя поля, как его пишет TS-плагин:

```pawn
if (xen_get_player_data(id, "ghost")) ...
xen_set_player_data(id, "ghost", 1);

new Float:speed = xen_get_player_data_float(id, "speed");
xen_set_player_data_float(id, "speed", 1.5);

new tag[32];
xen_get_player_data_string(id, "tag", tag, charsmax(tag));
xen_set_player_data_string(id, "tag", "VIP");

// Член поля-объекта: ключ с точкой.
new enabled[16];
xen_get_player_data_string(id, "semiclip.enabled", enabled, charsmax(enabled));
xen_set_player_data_string(id, "semiclip.enabled", "true");
```

| натив | что делает |
| --- | --- |
| `xen_get_player_data(id, const key[])` | числовое поле, целым; boolean - 1 или 0 |
| `xen_set_player_data(id, const key[], value)` | задаёт числовое или boolean-поле |
| `Float:xen_get_player_data_float(id, const key[])` | числовое поле как `Float` |
| `xen_set_player_data_float(id, const key[], Float:value)` | задаёт числовое поле |
| `xen_get_player_data_string(id, const key[], out[], len)` | строковое поле; возвращает число записанных байт, обрезает по границе буквы UTF-8 |
| `xen_set_player_data_string(id, const key[], const value[])` | задаёт строковое поле |

Поле, прочитанное как другой вид (строковое через `xen_get_player_data`),
читается как 0 или `""`. Юнион литералов - строка: `true | false | "default"`
- это `"true"`, `"false"` или `"default"`, а пока никто не писал - `""` (TS
читает это как первый литерал, `"default"`). `Player[]` - тоже строка, номера
через запятую: `"3,5"`.

`nhnse_get_user_bit` / `nhnse_set_user_bit` из nhnse остаются для собранных
модулей nhnse: для `BIT_GHOST`, `BIT_SEMICLIP_BLOCK` и `BIT_HIDE_TIMER` они
читают и пишут `player.ghost`, `player.semiclip.enabled == false` и
`player.hideTimer`; `nhnse_set_user_semiclip` ставит `player.semiclip.enabled`
(`SC_FORCE_ON` - `true`, `SC_FORCE_OFF` - `false`, `SC_DEFAULT` -
`"default"`); `nhnse_is_player_frozen` читает `player.frozen`.

Статус: поддельный сервер (`tests/player-fields.test.ts`); проверено на
тестовом сервере 2026-09-24 (`bun run test:server`, наборы `data-*`: один
TS-плагин пишет, другой читает, Pawn читает и пишет через нативы, а бот,
пришедший в тот же слот после кика, начинает с чистого листа). Поля-объекты,
`Player[]` и `Player.revision`: поддельный сервер (`tests/player-fields.test.ts`,
`tests/nhnse-core.test.ts`) и `bun run test:server` (`data-*`, 2026-09-24).
