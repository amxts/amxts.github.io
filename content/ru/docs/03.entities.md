const nade = new Entity(grenadeId);

## Как устроены свойства

У `Entity` — все поля `entvars` из reapi, у `Player` — ещё и все члены
`CBasePlayer` (и классов, от которых он наследуется). Тип свойства — тот, что
reapi документирует для поля:

| в reapi | свойство | тип |
| --- | --- | --- |
| `Float:get_entvar(id, var_gravity)` | `gravity` | дробное (`f64`) |
| `get_entvar(id, var_origin, Float:out[3])` | `origin` | читается `Vector`, пишется любой `number[]` из трёх |
| `get_entvar(id, var_classname, dest[], len)` | `classname` | `string` |
| `get_entvar(id, var_rendermode)` | `renderMode` | `number` |
| `get_member(id, m_bNightVisionOn)` | `nightVisionOn` | `boolean` |
| маска флагов (`var_flags`, `m_iHideHUD`, …) | `flags`, `hideHud`, … | массив имён, см. [Флаги](/ru/docs/flags) |

Имя — camelCase без префикса: `var_rendermode` → `renderMode`, `m_iHideHUD` →
`hideHud`, `m_flVelocityModifier` → `velocityModifier`. Имя из reapi — в
подсказке редактора при наведении.

Записать int-поле дробным (и наоборот) нельзя — не скомпилируется.

## Векторы - `Vector`

Статус: проверено на сервере 2026-09-23.

```ts
import { Player, Vector } from "~/facade";

const here = player.origin;                    // Vector
const away = here.distanceTo(other.origin);    // в юнитах
const up = new Vector(0.0, 0.0, 1.0);
player.velocity = here.subtract(target).normalize().scale(400).add(up.scale(200));
here.x; here[0];                               // одно и то же число
```

`add`, `subtract` и `distanceTo` принимают любые три числа, литерал тоже.
`scale(n)`, `dot(v)`, `normalize()` (длина 1; нулевой остаётся нулевым) и
`magnitude()` - длина вектора.

Под капотом `Vector` - массив из трёх чисел: поэтому литерал по-прежнему
присваивается, `origin[0]` читается, а натив с `Float:v[3]` принимает
`Vector`. Поэтому же длина - `magnitude()`, а не `length()`: `length` у
массива свой, и он равен 3.

## Поиск, создание, удаление

Статус: проверено на сервере 2026-09-23.

```ts
import { Entity } from "~/facade";

const targets = Entity.findAll({ classname: "info_target" });
const near = Entity.findAll({ near: player.origin, radius: 200 });
const mine = Entity.findAll({ classname: "grenade", owner: player });
const bomb = Entity.find({ model: "models/w_c4.mdl" });   // Entity | null

const box = Entity.create("info_target");                // Entity | null
if (box) box.origin = player.origin;

targets[0].remove();
```

Как `querySelectorAll`, `createElement` и `remove()`. Все поля фильтра
необязательны, совпасть должны все заданные; без фильтра `findAll()` - все
сущности. Работает на модуле engine, reapi не нужен.

`remove()` просит движок освободить сущность в конце кадра (`FL_KILLME`, так
уходят сущности самой игры), а не сразу, как `remove_entity`: сущность,
освобождённая из своего же touch или think или пока кто-то обходит список
сущностей, используется и после того, как её не стало. Поэтому в том же
кадре `findAll` её ещё находит.

## Написанные вручную

У `Player` есть свойства, которые берутся не из полей, а из нативов AMXX:
`name`, `health`, `armor`, `frags`, `deaths`, `team` (`"TERRORIST"`, `"CT"`,
`"SPECTATOR"`, `"UNASSIGNED"`), `ip`, `authid`, `isAlive`, `isConnected`,
`isBot`. Одноимённые поля reapi (`var_health`, `var_team`, …) у `Player` не
генерируются.

## Оружие — `Weapon`

Статус: проверено на сервере 2026-09-23.

```ts
import { Player } from "~/facade";
import { Weapon } from "~/entities";   // пока не реэкспортирован фасадом

const weapon = new Player(id).activeItem;    // Weapon | null
if (weapon && weapon.kind == "knife") {
	weapon.nextPrimaryAttack = 1.0;
}
weapon.clip = 0;
weapon.player                                 // Player | null — кто держит (m_pPlayer)
for (let i = 0; i < player.items.length; i++) console.log(player.items[i].kind);
```

- `Weapon extends Entity`: все entvar-свойства плюс члены `CBasePlayerItem`
  и `CBasePlayerWeapon` из `reapi_gamedll_const.inc`. Префикс `m_Weapon_`
  отбрасывается: `m_Weapon_iClip` → `clip`,
  `m_Weapon_flNextPrimaryAttack` → `nextPrimaryAttack`.
- `kind` — какое это оружие, строкой без `WEAPON_`: `"knife"`, `"flashbang"`,
  `"smokegrenade"`, `"hegrenade"`, `"ak47"`, … (тип `WeaponKind`; неизвестный
  id — `"none"`). `kindId` — то же числом, как константы `WEAPON_*`.
- Указатели — объекты: `player.activeItem` / `clientActiveItem` / `lastItem`
  — `Weapon | null`, `weapon.player` — `Player | null`, `weapon.next` —
  следующее оружие в том же слоте. Только чтение.
- `player.items` — всё оружие игрока: шесть слотов `m_rgpPlayerItems` и цепочки
  `m_pNext` за каждым (гранаты делят слот 4).
- `weapon.owner` — это `var_owner` из `Entity` (число), а держатель оружия —
  `weapon.player`: имя `owner` уже занято entvar'ом.

## Чего пока нет

- Поля-массивы (`m_rgAmmo`, …) — нужен индекс элемента; `m_rgpPlayerItems` закрыт через `player.items`.
- Строковые члены `m_*` (`m_szTeamName`, …) — упираются в передачу длины
  буфера в диспетчере.
- `var_controller`, `var_blending`.
